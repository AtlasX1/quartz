Мета: отримати глибоке розуміння архітектури баз даних, моделей збереження даних, транзакцій, індексації, оптимізації запитів, масштабування, а також особливостей SQL та NoSQL підходів.

---

## 1) 🧱 Relational Databases Structure & SQL

**Ціль:** глибоке розуміння реляційної моделі, нормалізації, ключів і складних SQL-запитів.

- **Концепції реляційної моделі:** таблиці, атрибути, записи, відношення.
- **Нормалізація:** 1NF, 2NF, 3NF, BCNF, денормалізація для performance trade-offs.
- **Ключі:** primary key, unique key, foreign key, composite key.
- **Joins:** INNER, LEFT, RIGHT, FULL, CROSS.
- **Складні запити:** підзапити, CTE (WITH), UNION/INTERSECT/EXCEPT.
- **Агрегації:** `GROUP BY`, `HAVING`, віконні функції (`ROW_NUMBER`, `RANK`, `LAG`).
- **Filtering:** `WHERE`, `IN`, `EXISTS`, `LIKE`, `CASE`.
- **Практика:** аналіз даних через SQL, побудова звітів і аналітичних запитів.
- **Оптимізація:** розуміння `EXPLAIN`/`EXPLAIN ANALYZE`, вибір правильних join-стратегій.

## 2) 💾 Transactions & Isolation Levels (ACID), Locking & MVCC

**Ціль:** розуміти як гарантується узгодженість даних і контроль конкурентності.

- **ACID-властивості:**
  - **Atomicity:** усе або нічого.
  - **Consistency:** збереження цілісності.
  - **Isolation:** незалежність транзакцій.
  - **Durability:** збереження після commit.
- **Ізоляційні рівні:** READ UNCOMMITTED, READ COMMITTED, REPEATABLE READ, SERIALIZABLE.
- **Феномени:** dirty read, non-repeatable read, phantom read.
- **Блокування:** 
  - Песимістичне (`SELECT ... FOR UPDATE`).
  - Оптимістичне (версії записів, timestamp-based control).
- **MVCC (Multiversion Concurrency Control):** принцип роботи PostgreSQL, InnoDB.
- **Deadlocks:** як виявляються, профілактика (lock ordering).

---

## 3) ⚡ Indexing & Query Optimization

**Ціль:** підвищити продуктивність запитів та розуміти, як працює пошук.

- **Індекси:** B-Tree, Hash, GiST, GIN, BRIN.
- **Composite indexes:** порядок колонок, prefix selectivity.
- **Partial indexes:** індексація підмножини даних.
- **Covering indexes:** `INCLUDE` columns.
- **Query planner:** як СУБД обирає стратегію виконання.
- **Execution plans:** `EXPLAIN`, `EXPLAIN ANALYZE`, `cost`, `rows`, `loops`.
- **Common bottlenecks:** full table scan, sort operations, nested loop joins.
- **Materialized views** та **query caching**.
- **Інструменти:** `pg_stat_statements`, `performance_schema`, `EXPLAIN (ANALYZE, BUFFERS)`.

---

## 4) 🧩 NoSQL Overview

**Ціль:** розуміти моделі NoSQL і коли їх застосовувати.

- **Типи моделей:**
  - Key-Value (Redis, DynamoDB).
  - Document (MongoDB, CouchDB).
  - Column-family (Cassandra, HBase).
  - Graph (Neo4j, Dgraph).
- **CAP-теорема:** Consistency, Availability, Partition tolerance.
- **BASE підхід:** Basically Available, Soft-state, Eventually consistent.
- **Порівняння з SQL:** коли NoSQL краще — масштабування, schema-free, write-heavy системи.
- **Data modeling:** embedding vs referencing, denormalization patterns.

---

## 5) 📜 Document Databases (MongoDB)

**Ціль:** розуміти структуру та ефективну схему документних баз.

- **Основи:** колекції, документи (JSON/BSON).
- **Схема:** schema-on-read, schema validation.
- **CRUD-операції:** insert, update, delete, find, aggregation pipeline.
- **Aggregation framework:** stages (match, group, project, lookup, unwind).
- **Індекси:** single field, compound, text, geospatial, TTL.
- **Transactions:** multi-document transactions (з MongoDB 4.0).
- **Реплікація і шардінг у MongoDB.**
- **Моделі даних:** reference vs embed, polymorphic patterns.

---

## 6) ⚙️ Key-Value Stores & Caching

**Ціль:** оптимізувати читання та зменшити навантаження на базу.

- **Redis:** in-memory key-value store, data structures (string, list, set, hash, sorted set).
- **Use-cases:** sessions, leaderboards, rate-limiting, pub/sub.
- **TTL та eviction policies (LRU, LFU).**
- **Persistence:** RDB, AOF, hybrid storage.
- **Memcached:** простий кеш для короткоживучих даних.
- **Кешування рівнів:**
  - Application-level (in-memory, Redis).
  - Query-level (ORM cache, prepared statements).
  - HTTP-level (CDN, reverse proxy).
- **Cache invalidation strategies:** time-based, event-based, write-through, lazy loading.

---

## 7) 🧬 Database Scalability (Replication & Sharding)

**Ціль:** масштабувати та забезпечити доступність даних.

- **Реплікація:**
  - Master-slave / primary-replica.
  - Synchronous vs asynchronous.
  - Read replicas & failover.
- **Шардінг:**
  - Range-based, hash-based, directory-based.
  - Auto-sharding (MongoDB, Vitess).
  - Balancing & re-sharding strategies.
- **Partitioning:** horizontal vs vertical.
- **Distributed consistency:** quorum reads/writes, eventual consistency.
- **Monitoring & observability:** replication lag, slow queries, deadlock detection.
- **Tools:** Patroni, ProxySQL, Vitess, Citus, MongoDB Atlas.

## 8) 📊 Query Design & Data Analysis

**Ціль:** створювати оптимальні аналітичні запити.

- **Window functions:** аналітика без group-by.
- **CTE (WITH)** для читабельності складних запитів.
- **Views & materialized views.**
- **Temporary tables** для складних pipelines.
- **Analytical DB:** ClickHouse, DuckDB, TimescaleDB.

---

## 9) 🔒 Data Integrity & Security

**Ціль:** забезпечити безпечне зберігання даних.

- **Constraints:** primary/foreign keys, check constraints.
- **Data validation:** на рівні бази і застосунку.
- **Encryption:** at rest (TDE), in transit (TLS), field-level encryption.
- **Auditing & logging:** `pg_audit`, `general_log`.
- **Role-based access control (RBAC).**
- **Backup & recovery:** WAL archiving, snapshots, point-in-time recovery (PITR).
