Мета: стати експертом у безпечній розробці, розуміти загрози безпеці веб-додатків, принципи шифрування, автентифікації, авторизації, управління вразливостями та безпечної мережевої взаємодії.

---

## 1) 🧱 Secure Coding Practices

**Ціль:** писати код, стійкий до атак і вразливостей.

- **Основні принципи:**
  - **Валідація вводу:** фільтрація, перевірка типів, довжини, діапазонів.
  - **Вихідна фільтрація:** escaping для HTML, JSON, SQL, CLI.
  - **Не довіряй користувачу:** будь-які дані ззовні потенційно небезпечні.
  - **Least Privilege:** мінімальні дозволи для виконання дій.
  - **Fail-Safe Defaults:** відмова за замовчуванням, якщо перевірка не пройдена.
  - **Avoid hardcoded secrets:** використання secret managers.
- **Типові вразливості:**
  - **XSS (Cross-Site Scripting)** — уникати вставки невалідаційного HTML.
  - **SQL Injection** — застосовувати prepared statements.
  - **CSRF (Cross-Site Request Forgery)** — токени перевірки запитів.
  - **Command Injection, Path Traversal, Insecure Deserialization.**
- **Інструменти:** ESLint security plugin, Bandit, SonarQube, Semgrep.

## 2) 🕸️ Web Application Security (OWASP Top 10)

**Ціль:** знати найпоширеніші вразливості веб-додатків і способи їхнього усунення.

| Категорія | Опис | Захист |
|------------|------|--------|
| **A1: Broken Access Control** | Неправильне обмеження дій користувачів. | RBAC, валідація прав на бекенді. |
| **A2: Cryptographic Failures** | Недостатній захист даних. | Використовувати TLS, AES, RSA, bcrypt. |
| **A3: Injection** | Небезпечні запити до БД чи інтерпретаторів. | Parameterized queries, escaping. |
| **A4: Insecure Design** | Недоліки у бізнес-логіці. | Threat modeling, DDD. |
| **A5: Security Misconfiguration** | Відкриті порти, default credentials. | Secure configs, minimal exposure. |
| **A6: Vulnerable Components** | Застарілі залежності. | Snyk, Dependabot, npm audit. |
| **A7: Identification & Auth Failures** | Ненадійна автентифікація. | JWT rotation, MFA. |
| **A8: Software & Data Integrity Failures** | Компрометовані CI/CD pipelines. | Sigstore, checksum validation. |
| **A9: Logging & Monitoring Failures** | Відсутність аудиту атак. | Centralized logging, alerting. |
| **A10: SSRF (Server-Side Request Forgery)** | Атаки через неконтрольовані URL. | Валідація зовнішніх запитів. |

## 3) 🔐 Authentication & Authorization

**Ціль:** забезпечити надійний доступ і контроль до ресурсів.

- **Authentication (Хто ти?):**
  - **JWT (JSON Web Token):** підписаний токен для безстанового доступу.
  - **OAuth 2.0 / OpenID Connect:** делегована авторизація.
  - **MFA (Multi-Factor Authentication):** підвищення безпеки.
  - **Password hashing:** bcrypt, Argon2, PBKDF2.
- **Authorization (Що ти можеш робити?):**
  - **RBAC (Role-Based Access Control):** доступ за ролями.
  - **ABAC (Attribute-Based Access Control):** динамічна авторизація.
  - **Principle of Least Privilege:** обмеження прав.
  - **Context-aware policies:** доступ залежно від IP, часу, пристрою.
- **Best practices:**
  - Використовуй refresh-токени з коротким TTL.
  - Rotate secrets і токени регулярно.
  - Не зберігай токени у localStorage → використовуй httpOnly cookies.

## 4) 🔑 Encryption & Cryptography

**Ціль:** забезпечити конфіденційність, цілісність і справжність даних.

- **Основні поняття:**
  - **Symmetric Encryption:** AES, ChaCha20.
  - **Asymmetric Encryption:** RSA, ECC.
  - **Hashing:** SHA-256, SHA-3, bcrypt (для паролів).
  - **Digital Signatures:** ECDSA, Ed25519.
  - **Key Exchange:** Diffie-Hellman, ECDH.
- **Керування ключами:**
  - Не зберігати ключі у репозиторії.
  - Використовувати менеджери ключів (AWS KMS, HashiCorp Vault).
  - Ротація ключів і токенів.
- **Data in Transit & at Rest:**
  - TLS/HTTPS — обов’язково.
  - Шифрування дисків (LUKS, BitLocker, EBS Encryption).
  - Tokenization для зберігання PII.

## 5) 🌐 Network Security Basics (SSL/TLS)

**Ціль:** захистити канали зв’язку між клієнтом і сервером.

- **SSL/TLS принципи:**
  - Handshake, certificates, cipher suites.
  - Mutual TLS (mTLS) для сервісів.
- **HTTPS best practices:**
  - Використовувати сучасні протоколи (TLS 1.2+).
  - HSTS (HTTP Strict Transport Security).
  - Вимкнення слабких алгоритмів (MD5, RC4, SHA1).
- **Certificates:**
  - Сертифікати від CA (Let’s Encrypt, AWS ACM).
  - Автоматичне оновлення (Certbot, Traefik).
  - Certificate pinning для мобільних клієнтів.

## 6) 🧰 Security Testing & Vulnerability Management

**Ціль:** системно виявляти, аналізувати та усувати вразливості.

- **Static Application Security Testing (SAST):**
  - Аналіз вихідного коду без запуску.
  - Інструменти: SonarQube, Semgrep, Bandit.
- **Dynamic Application Security Testing (DAST):**
  - Перевірка запущених додатків на вразливості.
  - Інструменти: OWASP ZAP, Burp Suite.
- **Dependency Scanning:**
  - Виявлення проблем у сторонніх бібліотеках.
  - Інструменти: Snyk, Dependabot, npm audit.
- **Penetration Testing:**
  - Ручні перевірки фахівців (internal/external pentest).
- **Vulnerability Lifecycle:**
  - Виявлення → класифікація → виправлення → перевірка → документування.
- **Patch Management:** регулярне оновлення компонентів.
