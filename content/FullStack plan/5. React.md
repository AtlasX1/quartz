Мета — дати **повний теоретичний план** до рівня L4: глибинне розуміння рендерингу, хуків, архітектури компонентів, продуктивності, серверних можливостей (RSC/SSR), тестування та доступності.

---

## 1) 🧱 React Core & Rendering Model

**Ціль:** чітко розуміти, що і коли рендериться, як працює reconcilation та ключі.

- **JSX/TSX як синтаксичний цукор** над `React.createElement`, правила як вирази перетворюються на дерево елементів.
- **Reconciliation & Diffing:** робота з **keys**, стабільність порядку, мінімізація повторного монтування.
- **Component types:** Function components (стандарт), класові — лише для легасі.
- **StrictMode:** подвійний виклик ефектів у дев-режимі, виявлення побічних ефектів.
- **Lifecycle у функціональних компонентах:** через хуки; чому класові lifecycle (componentDidMount тощо) більше не є must-have.
- **Controlled vs Uncontrolled components**, керування формами, refs.

---

## 2) 🧩 Component Architecture & Patterns

**Ціль:** створювати масштабовані, повторно використовувані компоненти з низькою зв’язністю.

- **Розділення відповідальностей:** контейнерні/презентаційні компоненти, Smart vs Dumb.
- **Патерни композиції:**
  - **Compound Components** (контролі, меню, таблиці з підкомпонентами).
  - **Render Props** (гнучке передавання поведінки).
  - **Higher-Order Components (HOC)** (для легасі, зважено).
  - **Control Props** та **State Reducer** (керування станом ззовні).
- **Поліморфні компоненти** (`as` prop), forwardRef, generic props із TypeScript.
- **Design System / UI Kit:** токени дизайну, темізація, узгоджені API.

## 3) 🪝 Hooks (Core, Additional, Performance, Experimental)

**Ціль:** володіти хуками та правильно застосовувати їх для керування станом і побічними ефектами.

### 3.1 Core Hooks
- `useState`, **lazy init**, функціональні оновлення.
- `useEffect` — **фази ефектів**, **cleanup**, **порядок виконання**, **залежності** (як уникати зайвих ререндерів), **ефекти vs події**.
- `useRef` — збереження мутабельних посилань, **не-тригерить ререндер**.
- `useContext` — коли варто/не варто, **селектори контексту** та мемоізація значень.

### 3.2 Additional Hooks
- `useReducer` (state machine, складні стани), `useLayoutEffect` (синхронізація із layout), `useImperativeHandle` (інтерфейс до внутрішніх методів), `useDebugValue` (для custom hooks).

### 3.3 Performance Hooks
- `useMemo` / `useCallback` — **коли вони дійсно потрібні**, залежності, вартість мемоізації.
- **Transition APIs:** `useTransition`, `startTransition` — розділення невідкладних/некритичних оновлень.
- `useDeferredValue` — відкладення важких рендерів.
- **Профі-тема:** уникати “мемо всього” — аналіз “allocation vs reuse”.

### 3.4 Нові/Серверні API в екосистемі React 18/19
- **React Server Components (RSC)** — компоненти без бандла на клієнт, **server-only** код.
- **Server Actions** (у фреймворках на кшталт Next.js App Router) — мутації на сервері з простим API.
- **useFormStatus / useActionState / useOptimistic** — покращені UX-патерни для форм та оптимістичних оновлень.

### 3.5 Custom Hooks
- Інкапсуляція логіки, реюз, **контроль залежностей**, тестованість.
- Приклади: доступність (focus-trap), мережеві стани, інтервали, синхронізація з URL.

## 4) 📦 State Management & Data Fetching

**Ціль:** вибирати правильний рівень стану та інструмент під сценарій.

- **Локальний стан:** `useState`/`useReducer`, lifting state up, context (для вузьких ділянок).
- **Глобальний стан:** 
  - **Redux Toolkit** (slices, RTK Query), **Redux-Saga** для складних побічних ефектів.
  - **Zustand** — простий глобальний стор, селектори, оптимізація з shallow.
- **Серверний стан:** **TanStack Query (React Query)**, **SWR** — кешування, рефетч, синхронізація з бекендом, **data + error + loading** патерн.
- **Форми та валідація:** **react-hook-form** (контролери, резольвери), інтеграція з **Zod/Yup**, тонкий контроль ререндерів.

## 5) 🖧 Routing & App Architecture

**Ціль:** розуміти маршрутизацію та сучасну архітектуру застосунків.

- **React Router** — data routers (loader/action), навігація, захищені маршрути.
- **Next.js (App Router):** RSC, layouts/slots, **SSR/SSG/ISR**, streaming, **Server Actions**, route-handlers, кеш-політики.
- Організація директорій, розподіл відповідальностей між **pages/layouts/components/hooks/lib**.

---

## 6) 🚀 Performance & Optimization

**Ціль:** створювати швидкі інтерфейси з контрольованими витратами рендерингу.

- **Рендерингова вартість:** що тригерить ререндер (props/state/context), як ізолювати.
- **Мемоізація компонентів:** `React.memo`, стабільність пропів, **structural sharing** (імм’ютабельні структури).
- **Списки:** ключі, **віртуалізація** (`@tanstack/react-virtual`, react-virtualized) для довгих таблиць/гридів.
- **Code splitting & Lazy:** `React.lazy`, `Suspense`, **route-level** та **component-level** спліт.
- **Concurrent features:** transitions/deferred, **avoid blocking** (web workers/batched updates).
- **Профілювання:** React DevTools Profiler, flamegraphs, пошук “wasted renders”.

## 7) 🧪 Testing (Unit, Integration, E2E)

**Ціль:** упевнено тестувати компоненти, хуки та асинхронні сценарії.

- **Unit/Integration:** **Jest + React Testing Library**, `screen`, `userEvent`, async util-и (`findBy*`), **act()**.
- **Моки/стаби:** network (MSW), storage, таймери.
- **E2E:** Playwright / Cypress — сценарії користувача, accessibility перевірки.
- **Контрактні тести** на корисні custom hooks / pure utils.

**Ціль:** підтримуваний підхід до стилів та темізації.

## 9) ♿ Accessibility (a11y) у React

**Ціль:** безбар’єрні інтерфейси.

- Лейбли форм, `aria-*`, **role**-атрибути, керування фокусом (особливо модальні/меню).
- **Keyboard nav:** `Tab`, `Esc`, focus traps, roving tabindex.
- **Live regions** (`aria-live`), оголошення помилок форм.
- Тестування a11y: axe, eslint-plugin-jsx-a11y, перевірка контрасту.

**Ціль:** контрольоване відновлення після помилок.

- **Error Boundaries** (класові на сьогодні, або обгортки для функціональних компонентів).
- Обробка помилок у data fetching (retry/backoff, fallback UI).
- Логування/сповіщення (Sentry, custom reporting), розрізнення expected/unexpected errors.

---

## 11) 🌐 RSC, SSR, Streaming & Hydration

**Ціль:** використовувати серверні можливості для продуктивності та DX.

- **React Server Components:** розділення клієнт/сервер, **server-only** модулі, zero-client JS.
- **Hydration:** часткова/селективна, проблеми з невизначеним станом на клієнті.
- **SSR/SSG/ISR** у Next.js, **streaming** відповідей, **Suspense на сервері**.
- **Кеш** на сервері: fetch cache, revalidate, `unstable_cache` (фреймворк-специфічно).

---

## 12) 🧭 Patterns for Data-Heavy UI

**Ціль:** будувати складні таблиці/списки/дешборди без втрати продуктивності.

- **Віртуалізація таблиць/гридів**, sticky headers/columns, динамічні висоти рядків.
- **Керована/некерована фільтрація/сортування/групування**, debounce/throttle.
- **Оптимальні структури даних** для lookup/updates (Map/Set, індексація, immutability).
- **Потокові оновлення** (SSE/WebSocket), оптимістичні апдейти, конфлікти.
