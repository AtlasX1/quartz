Мета цього гіда — дати **повний теоретичний план** знань, необхідних для рівня **L4 (Expert)** у TypeScript. Зосереджено на глибині мови, типізації, конфігурації компілятора, екосистемі та best practices.

---

## 1) 🧱 Basic Types & Syntax

**Ціль:** бездоганно орієнтуватися в базовій типізації та синтаксисі TS.

- **Примітиви:** `string`, `number`, `boolean`, `null`, `undefined`, `symbol`, `bigint`.
- **Об’єкти та масиви:** `object`, літерали об’єктів, кортежі (`[T, U]`), readonly-масиви (`readonly T[]` / `ReadOnlyArray<T>`).
- **Функції:** анотація параметрів/повертаного значення, опційні (`x?: T`), значення за замовчуванням, перевантаження (`function overloads`), this-параметр (`function f(this: SomeType, ...)`).
- **Енумерації:** `enum` (numeric/string), `const enum` (inline), trade-offs для tree-shaking/compat.
- **Літеральні типи:** string/number/boolean-literals, **union** з літералами.
- **`as const`** (const-assertions) — заморожування значень та найвужчі типи.

---

## 2) 🧩 Interfaces vs Type Aliases

**Ціль:** знати відмінності, сильні сторони та сценарії застосування.

- **Інтерфейси (`interface`):** декларативне розширення, _declaration merging_, розширення кількох інтерфейсів.
- **Аліаси типів (`type`)**: композиція через `&`/`|`, рекурсивні типи, `typeof`, `keyof`, `unique symbol`.
- **Коли що:** 
  - Відкриті API → `interface` (мерджинг, розширення).
  - Складні трансформації/юніони → `type`.
- **Сумісність:** структурна типізація (duck-typing), _excess property checks_, index signatures.

---

## 3) 🧠 Advanced Types — інструментарій експерта

**Ціль:** вільно працювати з узагальненнями, умовними/відображуваними типами та складними трансформаціями.

### 3.1 Generics
- **Параметри типів** з обмеженнями (`<T extends U>`), дефолтні параметри (`<T = unknown>`).
- **Перевантаження** та generic-функції/класи/інтерфейси.
- **Generic constraints & utility patterns:** `extends keyof`, `Record<K,V>`, `Partial<T>`, `Required<T>`, `Readonly<T>`, `Pick<T,K>`, `Omit<T,K>`.
- **Variance:** covariant/contravariant/invariant у функційних типах (позиції параметрів/результату).

### 3.2 Conditional Types
- Синтаксис: `T extends U ? X : Y`.
- **Distributive conditional types** (коли `T` — union).
- Оператор `infer` для виведення частин типу (наприклад, витяг типів аргументів/результату з функції).
- Приклади: `ReturnType<T>`, `Parameters<T>`, `InstanceType<T>`, власні екстрактори `ElementType<T>`.

### 3.3 Mapped Types
- `in keyof` і трансформації ключів, **опціональність** (`?`) та **readonly** модифікатори.
- Приклади: `Mutable<T>`, `DeepPartial<T>`, `DeepReadonly<T>`.
- **Key remapping:** `as` у mapped types для перейменування/фільтрації ключів.

### 3.4 Template Literal Types
- Комбінування літералів: `` type CSSVar = `--${string}` ``.
- Побудова **string unions** та перевірок форматів (`HexColor`, `RoutePath` тощо).

### 3.5 Tuples & Variadic Tuples
- Іменовані елементи кортежів, опційні/решта-елементи (`[head: T, ...rest: U[]]`).
- Побудова типів для curry/compose/route-params.

### 3.6 Utility Types — знати напам’ять
- `Partial`, `Required`, `Readonly`, `Pick`, `Omit`, `Record`, `NonNullable`, `Extract`, `Exclude`, `ReturnType`, `InstanceType`, `Parameters`, `ConstructorParameters`, `ThisType`, `Awaited`.

---

## 4) 🛡️ Type Guards & Narrowing

**Ціль:** правильно звужувати типи та уникати невичерпних гілок.

- **Нативні гард-функції:** `typeof`, `instanceof`, оператор `in`.
- **Потреба у користувацьких гард-функціях:** `function isFoo(x: unknown): x is Foo { ... }`.
- **Discriminated unions:** **discriminant field** та exhaustive-switch із _`never`-guard_ для повноти.
- **Налаштування строгих перевірок:** `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`.

---

## 5) ⚙️ TypeScript Configuration (tsconfig) — суворий режим експерта

**Ціль:** вміти налаштувати строгий, продуктивний і сумісний білд.

### 5.1 Strictness Suite
- `"strict": true` як маст-хев: включає `noImplicitAny`, `noImplicitThis`, `alwaysStrict`, `strictNullChecks`, `strictFunctionTypes`, `strictBindCallApply`, `strictPropertyInitialization`, `useUnknownInCatchVariables`.
- Рекомендовані:  
  - `"noUncheckedIndexedAccess": true`  
  - `"exactOptionalPropertyTypes": true`  
  - `"noPropertyAccessFromIndexSignature": true`  
  - `"noFallthroughCasesInSwitch": true`

### 5.2 Target/Module/Resolution
- `"target": "ES2022" | "ES2020"` (за потребою), `"module": "ESNext" | "NodeNext"`, `"moduleResolution": "Bundler" | "NodeNext"`.
- `"lib"`: DOM/ESNext/DOM.Iterable залежно від оточення.
- `"jsx": "react-jsx"`/`"react-jsxdev"` для React 17+.
- `"resolveJsonModule": true`, `"allowJs": true`, `"checkJs": true` для JS-інтеропу.
- `"esModuleInterop": true`, `"allowSyntheticDefaultImports": true` — сумісність із ESM/CJS.
- `"types"`/`"typeRoots"` — контроль над ambient-типами (наприклад, для Node/DOM).

### 5.3 Build Performance & Scale
- `"incremental": true`, `"composite": true` + **Project References** для монореп та великих проєктів.
- `"skipLibCheck": true` (з обережністю), `"sourceMap": true`, `"inlineSources": true`.
- `"isolatedModules": true"` для сумісності з SWC/Vite/ts-node ESM.
- `"useDefineForClassFields": true"` для узгодження із сучасною семантикою JS.

### 5.4 Path Mapping
- `"baseUrl": "."`, `"paths": { "@src/*": ["src/*"], "@tests/*": ["tests/*"] }` — та коректна підтримка у бандлерах (Vite/webpack/ts-jest).

## 6) 📦 Modules & Namespaces

**Ціль:** розуміти модульну систему та сумісність ESM/CJS.

- Перевага **ES Modules** (`import/export`) над `namespace` (тільки для спадку/legacy).
- **Ambient modules** (`declare module "pkg" { ... }`) — розширення сторонніх пакетів.
- **Re-exports**, `export type`, `import type`, ізоляція типів vs значень.
- **Side-effect imports** і tree-shaking, помітка `sideEffects` у `package.json`.

---

## 7) 🧾 Declaration Files & DefinitelyTyped

**Ціль:** вміти писати/доповнювати `.d.ts` для бібліотек.

- **Ambient declarations:** `declare global`, `declare namespace`, доповнення існуючих типів.
- **Модульні декларації:** `declare module`.
- **Publishing типів:** власний `types` entry у `package.json`, або `@types/*` у DT.
- **JS interop:** JSDoc-нотації (`/** @type {import('...').Type} */`), `"checkJs": true`.

---

## 8) 🧪 Decorators (experimental) & Metadata

**Ціль:** знати стан стандарту та застосування у фреймворках (NestJS, TypeORM).

- **`experimentalDecorators`** та **`emitDecoratorMetadata`** (reflect-metadata).
- Класи, методи, параметри, властивості — точки застосування.
- Обмеження типів під час рантайму, інверсія контролю/DI.
- Стан стандарту TC39 (legacy vs stage-3 decorators) і наслідки для конфігурації.

## 9) 🧰 Tooling & Build

**Ціль:** інтегрувати TS у справжній production-процес.

- **ESLint** з `@typescript-eslint/*` (TSLint — deprecated).
- **Build tools:** Vite, esbuild, SWC, webpack — сумісність з TS/paths/aliases.
- **Testing:** Vitest/Jest з `ts-jest` або трансформацією через Vite/SWC.
- **ts-node**, **tsx** для dev-run, ESM/TS сумісність.
- **tslib** + `"importHelpers": true` для зменшення бандлів.

---

## 10) 🧭 Patterns & Best Practices

**Ціль:** писати зрілий, підтримуваний код з сильною типобезпекою.

- **Discriminated unions** замість `tag`-less unionів.
- **Exhaustive checks** через `never` у `switch`.
- **`satisfies`** для валідації об’єктів проти типу без звуження значень.
- **Брендовані типи** (nominal-like) через `unique symbol`/інтерсекции.
- **Валідація runtime ↔ static:** `zod`, `io-ts`, `valibot` (узгодження типів і даних).
- **API типи:** DTOs, `as const` для стабільних літералів, `readonly` всюди, де можливо.
- **Avoid `any`**: використовуйте `unknown` + звуження/гварди.
- **Public API typing:** відокремлюйте внутрішні/зовнішні типи, `export type` для чистих типів.

## 11) 🌐 DOM, JSX/TSX та React-екосистема

**Ціль:** розуміти взаємодію з DOM-типами та JSX.

- `"lib": ["DOM", "DOM.Iterable", "ESNext"]` — коли потрібні DOM-типи.
- **JSX у TS:** `tsx`, `jsxImportSource` (для Emotion/Preact), `react-jsx` runtime.
- **Typing props/state/refs**, `React.FC` (коли не варто), `PropsWithChildren`, `ElementType`.
- Генерики для компонентів, поліморфні компоненти (`as`-prop), `forwardRef`, `memo`.
- Типізація подій, `CSSProperties`, `ReactNode` vs `JSX.Element`.

---

## 12) 🧬 Performance of the Type System

**Ціль:** уникати повільних типів і проблем з компілятором.

- Глибокі рекурсивні типи та вибухова дискретизація union-ів — як обмежувати складність.
- Розкладання умовних типів, уникнення величезних distributive conditional chains.
- Локалізація складних типів у `type-level modules`, вимірювання часу компіляції.

---

## 13) 🔄 Interop з JavaScript & Міграції

**Ціль:** безболісно переводити JS-код у TS.

- **`allowJs` + поступове додавання типів**, `@ts-check` у JS-файлах.
- **JSDoc типи** для плавної міграції, `// @ts-ignore`/`@ts-expect-error` — коли і як безпечно.
- **`unknown` поверх `any`**, обгортання сторонніх типів-`any` власними branded-типами.
- Міграція CRA → Vite/Next, налаштування `paths`, `moduleResolution`.
