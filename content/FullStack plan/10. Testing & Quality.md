Мета: досягти рівня експерта у тестуванні програмного забезпечення, розуміти методології, типи тестів, інструменти контролю якості та підходи до розробки через тестування.

---

## 1) 🧱 Unit Testing

**Ціль:** забезпечити коректність окремих модулів або функцій у ізоляції.

- **Призначення:** виявлення помилок у найменших одиницях коду (функції, класи, методи).
- **Принципи unit-тестів:**
  - Малі, ізольовані, швидкі.
  - Не залежать від зовнішніх систем (БД, API).
  - Використовують mocks/stubs для залежностей.
- **Структура тесту:** Arrange → Act → Assert (AAA).
- **Критерії якості тестів:**
  - **Repeatable:** стабільний результат.
  - **Deterministic:** не залежить від порядку чи середовища.
  - **Readable:** зрозумілий намір тесту.
- **Фреймворки:** Jest, Mocha, Vitest, Jasmine, xUnit, PyTest, JUnit.
- **Coverage:** функціональне (line, branch, statement), але без фетишу на 100%.

---

## 2) 🔗 Integration Testing

**Ціль:** перевірити, як взаємодіють різні модулі або системи.

- **Призначення:** упевнитися, що окремі компоненти працюють разом правильно.
- **Приклади:**
  - Тести API endpointів через HTTP-запити.
  - Перевірка ORM-з’єднання з базою.
  - Тестування middleware або cache layer.
- **Підходи:**
  - **Top-down / Bottom-up:** залежно від структури системи.
  - **Hybrid approach:** тестування критичних шляхів.
- **Ізоляція:** використовуються **mocked** або **in-memory** залежності (sqlite-in-memory, Redis-mock).
- **Інструменти:** Supertest, Testcontainers, WireMock, MSW, Docker Compose для інфраструктурних тестів.

---

## 3) 🧩 Mocking & Stubbing

**Ціль:** відокремити код від зовнішніх залежностей для стабільного тестування.

- **Mocks:** об’єкти, які перевіряють виклики (expectations).
- **Stubs:** підставні об’єкти, що повертають фіксовані значення.
- **Fakes:** спрощені реалізації (наприклад, in-memory DB).
- **Spies:** обгортки, які збирають інформацію про виклики.
- **Приклади використання:**
  - Ізоляція від API або баз даних.
  - Контроль сценаріїв успіху/помилки.
  - Тестування поведінки без залежності від середовища.
- **Бібліотеки:** Jest (jest.fn, mocks), Sinon, Nock, MSW, Mockito, ts-mockito.

## 4) 🧠 Test-Driven Development (TDD) & Behavior-Driven Development (BDD)

**Ціль:** використовувати тестування як рушій проектування коду та поведінки системи.

### TDD (Test-Driven Development)
- **Цикл Red → Green → Refactor:**
  1. Напиши тест, який падає.
  2. Реалізуй мінімальний код, щоб тест пройшов.
  3. Оптимізуй код без зміни поведінки.
- **Переваги:**
  - Мінімум надлишкового коду.
  - Чіткі вимоги до API.
  - Легша рефакторизація.

### BDD (Behavior-Driven Development)
- **Ціль:** описувати поведінку системи природною мовою.
- **Синтаксис Given–When–Then:**
  - **Given:** початковий контекст.
  - **When:** дія.
  - **Then:** очікуваний результат.
- **Інструменти:** Cucumber, Gherkin, Jest + describe/it, Behave.
- **Переваги:**
  - Порозуміння між технічними і бізнес-командами.
  - Валідація вимог до поведінки системи.

## 5) 🧰 Static Code Analysis & Quality

**Ціль:** автоматично контролювати якість і безпеку коду.

- **Статичний аналіз:** перевірка коду без запуску.
- **Цілі:**
  - Виявлення помилок, smells, антипатернів.
  - Підтримання стандартів стилю й якості.
  - Виявлення потенційних уразливостей.
- **Інструменти:**
  - **JavaScript/TypeScript:** ESLint, SonarQube, CodeQL, DeepScan.
  - **Python:** Pylint, mypy, Bandit.
  - **Java:** Checkstyle, PMD, SpotBugs.
- **Метрики якості:**
  - Cyclomatic complexity.
  - Code duplication.
  - Test coverage.
- **CI/CD інтеграція:** запуск lint, static analysis і security scan перед merge.

---

## 6) 🧾 Quality Assurance & CI/CD Integration

**Ціль:** гарантувати, що якість коду підтримується на всіх етапах розробки.

- **QA стратегія:** unit → integration → E2E → regression → smoke.
- **Test pyramid:** багато unit-тестів, менше інтеграційних, мінімум E2E.
- **Automation:** GitHub Actions, GitLab CI, Jenkins, CircleCI.
- **Code review culture:** чіткі критерії (readability, test coverage, maintainability).
- **Defect prevention:** лінтери, pre-commit hooks (Husky), typed code.
- **Metrics:** test pass rate, MTTR, escaped defects.
