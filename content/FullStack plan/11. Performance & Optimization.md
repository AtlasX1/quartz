Мета: стати експертом у виявленні, вимірюванні та усуненні вузьких місць продуктивності у застосунках, базах даних та мережевій взаємодії.

---

## 1) 🧵 Concurrency Performance Tuning

**Ціль:** оптимізувати паралельне виконання, мінімізувати блокування і збільшити пропускну здатність системи.

- **Основні концепції:**
  - **Parallelism vs Concurrency:** одночасне виконання завдань проти розпаралелювання.
  - **Contention:** блокування ресурсів при спільному доступі.
  - **Granularity:** баланс між кількістю потоків і розміром завдань.
- **Техніки оптимізації:**
  - Зменшення lock contention: перехід до lock-free структур або fine-grained locking.
  - Використання thread pool з оптимальним розміром (CPU-bound vs I/O-bound).
  - Використання **asynchronous/non-blocking APIs** для масштабування.
  - **Task batching** — об’єднання дрібних завдань у великі блоки.
- **Паралельне виконання у Node.js:** event loop, worker threads, message passing.
- **Профі-тема:** Amdahl’s law, false sharing, memory barriers, NUMA-awareness.

---

## 2) 🌐 I/O and Network Optimization

**Ціль:** усунути затримки в обміні даними, файловому доступі та мережевих викликах.

- **Типи I/O:**
  - Blocking vs Non-blocking vs Asynchronous I/O.
  - Synchronous APIs викликають затримку через очікування.
- **Оптимізаційні техніки:**
  - Використання буферів і **stream-based** читання/запису.
  - **Connection pooling** — повторне використання відкритих з’єднань.
  - Зменшення **RTT (round-trip time)** і пакетної обробки запитів.
  - **Compression & chunked transfer encoding** для HTTP.
  - Вибір протоколів (HTTP/2, gRPC, WebSockets) під сценарій.
  - **Asynchronous drivers** (наприклад, `pg` у Node.js, async JDBC).
- **Інструменти:** `curl -w`, Wireshark, Apache Bench, autocannon, iostat, dstat.
- **Профі-тема:** TCP slow start, congestion window tuning, Nagle’s algorithm.

## 3) 🧮 Database Performance Tuning

**Ціль:** оптимізувати запити, індексацію та паралельний доступ до баз даних.

- **Основні напрямки оптимізації:**
  - **Індексація:** використання B-tree, Hash, GIN, Composite index.
  - **Query execution plans:** аналіз через `EXPLAIN ANALYZE`.
  - **Locking overhead:** уникнення довгих транзакцій і full table scans.
  - **Connection pooling:** PgBouncer, HikariCP, TypeORM connection pools.
  - **Partitioning / Sharding:** розподіл великих таблиць для зменшення latency.
  - **Caching:** query-level cache (Redis, Memcached), prepared statements.
  - **Avoiding N+1 queries:** застосування join або batch fetching.
- **Інструменти:**
  - PostgreSQL: `pg_stat_statements`, `auto_explain`.
  - MySQL: `EXPLAIN FORMAT=JSON`, `performance_schema`.
  - MongoDB: `explain("executionStats")`, профайлер.
- **Профі-тема:** query planner hints, statistics, I/O cost modeling.

## 4) 💾 Caching Strategies

**Ціль:** використовувати кешування для зменшення навантаження та покращення швидкодії.

- **Основні принципи:**
  - Кешування результатів, які часто використовуються.
  - TTL (Time-To-Live) — час життя кешу.
  - Eviction policies: **LRU (Least Recently Used)**, **LFU (Least Frequently Used)**, FIFO.
  - **Lazy loading vs Write-through vs Write-behind** кешування.
- **Типи кешів:**
  - **In-memory:** швидкодія, але втрата при рестарті.
  - **Distributed:** Redis, Memcached — для масштабування.
  - **Application-level caching:** memoization, DataLoader (GraphQL).
  - **Database caching:** materialized views, query results.
- **Cache invalidation:**
  - Event-based (на зміну даних).
  - Time-based (TTL).
  - Manual / selective.
- **Профі-тема:** multi-layer caching, cache stampede prevention, Bloom filters.

## 5) 🧭 Profiling & Monitoring

**Ціль:** виявити вузькі місця продуктивності та забезпечити безперервне спостереження за системою.

- **Профілювання:**
  - CPU profiling, heap snapshots, async flamegraphs.
  - Memory leaks, GC pauses, I/O wait time.
  - **Інструменти:**  
    - Node.js: `--inspect`, Chrome DevTools, Clinic.js.  
    - Java: VisualVM, JFR (Java Flight Recorder), YourKit.  
    - Python: cProfile, PySpy.  
- **Моніторинг:**
  - Application metrics: latency, throughput, error rate, saturation (USE/RED).
  - **APM (Application Performance Monitoring):**
    - New Relic, Datadog, Grafana, Prometheus, OpenTelemetry.
  - Alerting: SLA/SLO/SLI, anomaly detection.
- **Логування:** структуровані логи, кореляційні ID, tracing між сервісами.
- **Профі-тема:** observability-driven development, tracing sampling strategies.
