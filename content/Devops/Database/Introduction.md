Бази даних у DevOps – це одна з ключових складових, адже практично кожен застосунок взаємодіє з даними. У рамках DevOps, робота з базами даних передбачає автоматизацію, контроль версій та інтеграцію змін до баз даних у CI/CD-процеси.

### 📌 Основні поняття:

#### 1. **Infrastructure as Code (IaC)**

DevOps спеціалісти використовують IaC для автоматичного створення інфраструктури, включно з базами даних. Наприклад, можна автоматично розгорнути PostgreSQL через Terraform або Ansible.

#### 2. **Міграції баз даних**

Це контрольоване внесення змін у схему бази. Для цього використовують інструменти як:
- **Flyway**
- **Liquibase**
- **Alembic (для Python)**

Ці інструменти дозволяють вести історію змін і відкат, якщо щось пішло не так.

#### 3. **CI/CD інтеграція**

Зміни в базі можуть автоматично застосовуватись під час деплою нової версії застосунку. Наприклад:

`# GitLab CI приклад: застосування міграцій Flyway apply_migrations:   stage: deploy   image: flyway/flyway   script:     - flyway -url=jdbc:postgresql://db:5432/mydb -user=user -password=pass migrate`

#### 4. **Моніторинг і резервне копіювання**

База даних має бути не тільки налаштована, але й моніторитися (наприклад, через Prometheus+Grafana) та регулярно бекапитися (через `pg_dump`, `mysqldump`, або спеціальні сервіси).

#### 5. **Контейнери для баз даних**

Під час розробки DevOps часто використовують Docker для підняття локальної бази:

`# docker-compose.yaml приклад для PostgreSQL services:   db:     image: postgres:15     environment:       POSTGRES_USER: user       POSTGRES_PASSWORD: pass       POSTGRES_DB: mydb     ports:       - "5432:5432"`

---

### ✨ DevOps mindset до баз даних:

- **Автоматизуй усе**: створення, налаштування, тестування, резервне копіювання.
- **Контролюй версії**: уся схема БД має бути у репозиторії.
- **Тестуй**: застосування міграцій має перевірятись у staging середовищі.
