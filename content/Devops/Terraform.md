Terraform — це інструмент для **інфраструктури як коду (IaC)**, який дозволяє визначати та керувати інфраструктурою за допомогою конфігураційних файлів. Він був розроблений компанією **HashiCorp** і є надзвичайно популярним серед DevOps-інженерів.

## 🔧 Основні можливості Terraform

1. **Інфраструктура як код (IaC)** – інфраструктура описується у вигляді текстових файлів з розширенням `.tf`.
2. **Декларативний синтаксис** – ви описуєте _що_ ви хочете отримати, а не _як_ цього досягти.
3. **Підтримка багатьох провайдерів** – AWS, Azure, GCP, Kubernetes, GitHub, Cloudflare тощо.
4. **Планування змін** – перед застосуванням Terraform покаже, що саме буде створено/змінено/видалено (`terraform plan`).
5. **Керування станом (state)** – Terraform зберігає стан вашої інфраструктури у спеціальному файлі (`terraform.tfstate`).

## 🧱 Основні компоненти Terraform

|Компонент|Пояснення|
|---|---|
|**Providers**|Визначають, з якими сервісами працювати (наприклад, AWS, Azure)|
|**Resources**|Конкретні об’єкти, які створює Terraform (наприклад, EC2, S3)|
|**Variables**|Змінні для параметризації конфігурації|
|**Output values**|Виводять інформацію після застосування (наприклад, IP-адресу інстансу)|
|**Modules**|Повторно використовувані частини коду|
## 📦 Простий приклад: створення EC2 інстансу в AWS

```
provider "aws" {
  region = "us-east-1"
}

resource "aws_instance" "example" {
  ami           = "ami-0c55b159cbfafe1f0" # Amazon Linux 2 AMI
  instance_type = "t2.micro"

  tags = {
    Name = "MyInstance"
  }
}
```

Команди для роботи:
```
terraform init    # ініціалізація
terraform plan    # перегляд, що буде зроблено
terraform apply   # застосування змін
terraform destroy # видалення ресурсів
```

## 📘 Де це застосовується?

Terraform активно використовується для:
- Автоматизації хмарної інфраструктури
- CI/CD-пайплайнів
- Масштабування інфраструктури
- Синхронізації між різними середовищами (dev/staging/prod)
