### ❓ **Питання 1:**

> _How to copy a `text.t` file to `info.t`?_

---

### 🧠 **Пояснення для всіх варіантів:**

|Варіант|Команда|Пояснення|
|---|---|---|
|**a**|`copy text.t info.t`|❌ **Неправильно.** Це команда з Windows CMD, у Linux вона не працює.|
|**b**|`cat text.t > info.t`|⚠️ **Можна, але...** Створить копію, але перезапише файл `info.t`, якщо він вже існує. Не є "коректним" методом копіювання.|
|**✅ c**|`cp text.t info.t`|✅ **Правильно.** Стандартна Linux-команда для копіювання файлів.|
|**d**|`mv text.t info.t`|❌ **Неправильно.** Це **переміщення**, а не копіювання — файл `text.t` зникне.|
|**e**|`rm text.t info.t`|❌ **Небезпечно.** Видаляє обидва файли. Ніякого копіювання не відбувається.|

### ❓ **Питання 3:**

> _How to create a hard link `text.lnk` in the current folder on the `text.t` file?_

---

### 🧠 **Пояснення для кожного варіанту:**

|Варіант|Команда|Пояснення|
|---|---|---|
|**a**|`ln -s text.t text.lnk`|❌ **Це символьне (symbolic) посилання**, а не жорстке (hard link).|
|**b**|`ln -s text.lnk text.t`|❌ **Неправильний порядок аргументів** і знову ж таки — це `symbolic link`.|
|**✅ c**|`ln text.t text.lnk`|✅ **Правильно.** Це створює **жорстке посилання** `text.lnk` на файл `text.t`.|
|**d**|`ln text.lnk text.t`|❌ Зворотній порядок — створюється посилання навпаки. Не те, що вимагає питання.|
|**e**|There is no correct answer|❌ Є правильна відповідь — це варіант **с**.|

---

### 🔍 Що таке **hard link**?

- Це **альтернативне ім’я для того самого вмісту файлу**.
- Обидва файли вказують на **одну і ту саму інформацію на диску (inode)**.
- Якщо видалити один — другий **залишається працюючим**.

### ❓ **Питання 4:**

> _How to create a soft link to a `text.t` file?_

---

### 🧠 **Пояснення для кожного варіанту:**

|Варіант|Команда|Пояснення|
|---|---|---|
|**a**|`ln text.lnk text.t`|❌ Це жорстке посилання (hard link), і аргументи розташовані у зворотному порядку.|
|**b**|`ln text.t text.lnk`|❌ Це знову ж таки **hard link**, а не **soft link**, який вимагається.|
|**✅ c**|`ln -s text.t text.lnk`|✅ **Правильно.** Створює **symbolic link** з іменем `text.lnk`, що вказує на `text.t`.|
|**d**|`ln -s text.lnk text.t`|❌ Аргументи переплутано місцями — посилання вказує в зворотному напрямку.|
|**e**|There is no correct answer|❌ Є правильна відповідь — це варіант **с**.|

---

### 🔍 Що таке **symbolic (soft) link**?

- Це **ярлик**, який вказує на інший файл або каталог.
- Може вказувати на файл **у будь-якому місці файлової системи**.
- Якщо оригінальний файл видалено — посилання "ламається".

### ❓ **Питання 5:**

> _How to create an empty `text.t` file by means of Bash?_

---

### 🧠 **Пояснення для кожного варіанту:**

|Варіант|Команда|Пояснення|
|---|---|---|
|**a**|`cat /dev/null > text.t`|✅ **Працює.** Виводить "нічого" з `/dev/null` у файл — ефективно очищає або створює порожній файл.|
|**✅ b**|`touch text.t`|✅ **Найбільш рекомендований спосіб.** Створює порожній файл або оновлює час доступу/модифікації, якщо файл вже існує.|

|**✅ d**|`echo > text.t`|✅ **Працює.** Команда `echo` без тексту і з перенаправленням створює/очищає файл.|
|**✅ e**|`> text.t`|✅ **Працює.** Порожнє перенаправлення `>` створює або очищає файл — коротко і ефективно.|

---

🔔 **Порада:** У DevOps найчастіше використовують `touch`, бо воно **не змінює вміст файлу**, якщо він вже існує.

### ❓ **Питання 10:**

> _How to get a list of files starting with the 'F' letter?_

---

|Варіант|Команда|Пояснення|
|---|---|---|
|**❌ a**|`ls *F`|Показує файли, які **закінчуються** на `F`, а не починаються з неї.|
|**❌ b**|`ls F`|Працює лише, якщо існує **файл з точним ім’ям `F`**. Це не шаблонний пошук.|
|**❌ c**|`ls -F`|Це **опція**, яка додає символи (`/`, `*`) до імен файлів, але **не фільтрує список**.|
|**❌ d**|`ls .F`|Шукає **прихований файл з ім’ям `.F`**, що не відповідає умовам завдання.|
|**✅ e**|`ls F*`|**Правильна відповідь.** Виводить усі файли, які **починаються з літери `F`**.|

---

### ℹ️ **Коротка довідка:**

- `*` — символ шаблону, який означає "будь-що або нічого після".
- `ls F*` — знайде, наприклад: `File.txt`, `Folder`, `F1`, але не `file.txt`.
- Також можна використовувати інші шаблони:
  ```ls *.log       # усі файли з розширенням .log
ls A???.txt    # файли, які починаються на A і мають рівно 3 символи перед .txt
```


### ❓ **Питання 11:**

> _How to make `script.sh` script executable for owner only?_

---

|Варіант|Команда|Пояснення|
|---|---|---|
|**❌ a**|`chmod 755 script.sh`|Дає **власнику, групі й іншим**: читання та виконання. ❌ Скрипт буде виконуваним для всіх.|
|**❌ b**|`chmod 777 script.sh`|**Повні права для всіх** (читання, запис, виконання). ❌ Занадто небезпечно і не те, що треба.|
|**✅ c**|`chmod 744 script.sh`|✅ **Власник має повні права**, а інші — лише читання. **Виконувати може тільки власник.**|
|**❌ d**|`chmod 144 script.sh`|❌ Лише **виконання** для власника, читання для інших. Немає права на читання для самого власника.|
|**❌ e**|`chmod 155 script.sh`|❌ Дає виконання всім, але читання — тільки іншим. Скрипт буде "закритий" для читання власнику.|

---
### ℹ️ **Коротка довідка:**

- Формат `chmod XYZ`:
    - **X** — права для **власника** (user)
    - **Y** — права для **групи** (group)
    - **Z** — права для **інших** (others)
- **Цифри означають:**
    - `7` — читання + запис + виконання
    - `6` — читання + запис
    - `5` — читання + виконання
    - `4` — читання
    - `1` — виконання
    - `0` — без доступу

### ❓ **Питання 12:**

> _How to make the `script.sh` file executable for all users?_

---

| Варіант | Команда                          | Пояснення                                                                                                |
| ------- | -------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **❌ a** | `chmod u+w, g+r, g+x script.sh`  | ❌ Дає права лише **користувачу та групі**, а **іншим — нічого**. Не забезпечує виконання для всіх.       |
| **❌ b** | `chmod g+w, u+r, u+x script.sh`  | ❌ Дає лише часткові права **користувачу та групі**, **інших не зачіпає**.                                |
| **❌ c** | `chmod u+w, ug+r, u+x script.sh` | ❌ Знову ж таки, **немає прав для "others"**, тому скрипт не буде виконуватись усіма.                     |
| **✅ d** | `chmod a+w, a+r, a+x script.sh`  | ✅ **Правильна відповідь.** `a` означає **all (всі)**. Це надає **читання, запис та виконання для всіх**. |
| **❌ e** | `chmod u+w, ug+r, a+x script.sh` | ❌ Частково правильно, але не надає **читання для всіх**, лише виконання. Недостатньо.                    |
|         |                                  |                                                                                                          |

---

### ℹ️ **Коротка довідка:**

- `chmod` підтримує символьні позначення:
    - `u` — user (власник)
    - `g` — group
    - `o` — others
    - `a` — all (всі)
- Додати право:
    - `+r` — читання
    - `+w` — запис
    - `+x` — виконання

### ❓ **Питання 16:**

> _How to view a list of files with rights access?_

---

|Варіант|Команда|Пояснення|
|---|---|---|
|**❌ a**|`ls`|❌ Показує лише список файлів і папок без додаткової інформації, **прав доступу не видно**.|
|**✅ b**|`ls -al`|✅ Показує **усі файли (включно з прихованими)** з деталями: права доступу, власник, розмір тощо.|
|**✅ c**|`ls -l`|✅ Також правильна відповідь — показує **детальну інформацію про файли**, включаючи права доступу.|
|**❌ d**|`ls -a`|❌ Показує **всі файли, включно з прихованими**, але **без прав доступу**.|
|**❌ e**|`ls -F`|❌ Додає символи (`/`, `*` тощо) до імен файлів, але **не показує інформацію про права доступу**.|

---

### ℹ️ **Коротка довідка:**

- `ls -l` — показує:
    `-rw-r--r-- 1 user group 1234 Apr 7 14:30 file.txt`
    Де `-rw-r--r--` — це **права доступу**:
    - `r` — читання (read)
    - `w` — запис (write)
    - `x` — виконання (execute)
- `ls -al` = `-a` (всі файли) + `-l` (детальна інформація)

### ℹ️ **Коротка довідка:**

    - `ls -a` — показує всі файли

|**❌ e**|`cd .`|❌ Залишаєшся **в поточній папці** — не відбувається ніякого переходу.|

---

### ℹ️ **Коротка довідка:**

- `cd ..` або `cd ../` — переміщення **в батьківський каталог**
- `cd` — повертає у **домашню директорію** (`/home/ім’я_користувача`)
- `cd /` — у **корінь системи**
- `cd .` — **залишитись у тій самій папці**

### ❓ **Питання 33:**

> _You are in the root directory. How to find the `text.t` file in the file system?_

---

|Варіант|Команда|Пояснення|
|---|---|---|
|**✅ a**|`find . -name text.t`|✅ Пошук від **поточної директорії** (в даному випадку — `/`). Знайде `text.t` в усій системі.|
|**✅ b**|`find / -name text.t`|✅ Те ж саме, але **явно вказано корінь (`/`)** — знайде `text.t` по всій файловій системі.|
|**❌ c**|`find / -path text.t`|❌ `-path` шукає **повний шлях**, і тут не вказано, де саме знаходиться `text.t`. Не спрацює.|
|**❌ d**|`which text.t`|❌ `which` шукає **виконувані файли в $PATH**, а не звичайні файли.|
|**✅ e**|`locate "text.t"`|✅ Працює, **якщо є оновлений індекс `locate`**. Дуже швидкий, але може бути неактуальний.|

---

### ℹ️ **Коротка довідка:**

- `find / -name text.t` — повільніше, але на 100% надійно, бо реально проходить всю систему
- `locate text.t` — миттєвий результат, **але спирається на індексацію** (може бути застарілою)
