## 📊 **`htop`** — інтерактивна альтернатива `top`

### 🔹 Основні можливості:

- Показує використання CPU, пам’яті, swap.
- Перелік процесів з кольоровим інтерфейсом.
- Можна **вбивати процеси** напряму (F9).
- Фільтрування, сортування, дерево процесів (F5).

### 🔧 Встановлення:

``
```
sudo apt install htop
```
### 🔥 Команда запуску:

```bash
htop
```

🔸 Інтуїтивно зрозумілий, часто використовується для швидкої перевірки навантаження на систему.

---

## 🔁 **`btop`** — сучасний, візуально привабливий монітор

### 🔹 Основні фішки:

- Дуже гарний **TUI (text user interface)**.
- Графіки в реальному часі (CPU, RAM, диски, мережа).
- Простий навігаційний інтерфейс.
- Підтримка миші.

### 🔧 Встановлення:

```bash
sudo apt install btop
```

(або новішу версію з GitHub, якщо треба)

### 🔥 Запуск:

```bash
btop
```

🔸 `btop` — це оновлений варіант `bpytop`, написаний на C++, дуже легкий та швидкий.

---

## 🛠 **`atop`** — системний монітор з **акцентом на логування**

### 🔹 Чим особливий:

- Зберігає **історію використання ресурсів** (в логах).
- Детальне логування по **I/O, процесам, пам’яті, дисках**.
- Можна дивитись стан системи **в минулому**.
- Корисний для **діагностики "чому щось зависло вчора вночі"**.

### 🔧 Встановлення:

```bash
sudo apt install atop
```

### 🔥 Запуск:

```bash
atop
```

### ⏱ Програвання логів:

```bash
atop -r /var/log/atop/atop_YYYYMMDD
```

🔸 `atop` за замовчуванням запускається як сервіс і пише лог кожні 10 хв.

## 📟 Загальна структура `htop`

Коли ти запускаєш `htop`, бачиш щось подібне до:

```less
  1  [|||||||  40.0%]   Tasks: 93, 228 thr; 1 running
  2  [|||       20.0%]   Load average: 0.45 0.30 0.20
  Mem[||||||   3.2G/8.0G]   Uptime: 00:45:13
  Swp[|        256M/2.0G]
```

### 🔹 1. **CPU (рядки з цифрами 1, 2...)**

Показує завантаження кожного ядра процесора:
- `|` — графік.
- `%` — скільки зайнято.
- Зазвичай кольори:
    - **синій** — низький пріоритет (nice).
    - **зелений** — користувацькі процеси.
    - **червоний** — ядро (kernel).

---

### 🔹 2. **Memory (Mem)**

Використання оперативної пам’яті:
- `3.2G/8.0G` — скільки зайнято / всього.
- Частина може кешуватись, тобто не все — "активно використовується".

---

### 🔹 3. **Swap (Swp)**

- Якщо тут більше 0, значить **оперативної пам’яті не вистачає**, і система скидає частину в своп — це **погано для продуктивності**.

---

### 🔹 4. **Tasks / Threads**

- Кількість процесів і потоків.
- `running` — скільки з них зараз активно використовують CPU.

---

### 🔹 5. **Load Average**

Три числа — **середнє навантаження за останні**:
- 1 хвилину
- 5 хвилин
- 15 хвилин

📌 Наприклад: `0.45 0.30 0.20` означає, що навантаження не дуже велике.

> 🧠 **Порада:** Якщо навантаження більше, ніж кількість CPU ядер — система перевантажена.

---

### 🔹 6. **Uptime**

Скільки часу працює система без перезавантаження.

---

## 🔥 Порада для DevOps-практики

- Якщо CPU на 100% → дивись які процеси зверху.
- Якщо RAM забита → глянь на `RES` / `VIRT`.
- Використовуй `F5`, щоб побачити **який процес кого породив** (tree view).

## 🖥 Інтерфейс `btop`: верхня частина

Вікно `btop` поділено на **п'ять основних блоків**:
### 🔹 1. **CPU**

- Показує кожне ядро CPU з графіком і відсотком завантаження.
- Є дані по:
    - System (ядро)
    - User (користувацькі процеси)
    - Idle (простає)
    - Temp (температура, якщо доступна)
    - Frequency (частота)

📊 Графік дає зрозуміти, чи процесор постійно навантажений чи "стрибає".

---
### 🔹 2. **Memory / Swap**

- **RAM:** відображає загальну і використану пам’ять.
- **Swap:** скільки даних записано у своп.
- Показує кеш, буфери — все зручно і в кольорі 💡

📌 Якщо бачиш активний своп — значить оперативної пам’яті не вистачає.

---
### 🔹 3. **Disks**
- Показує завантаження дисків — читання / запис.
- Графіки з I/O-активністю.
- Корисно для виявлення "дискових вузьких місць".

---
### 🔹 4. **Network**

- Вхідний та вихідний трафік.
- Швидкість передавання даних в реальному часі.

📌 Якщо щось "завантажує" мережу — тут ти це точно побачиш 🚀

---
### 🔹 5. **Processes**

Найбільший блок — **таблиця активних процесів**, подібна до `htop`:

|Поле|Пояснення|
|---|---|
|**PID**|ID процесу|
|**User**|Хто запустив|
|**CPU%**|Скільки процес використовує CPU|
|**MEM%**|RAM|
|**Time**|Скільки працює|
|**Command**|Назва процесу|

---
## ⌨️ Керування в `btop`

- **Стрілки (↑↓)** — навігація по процесах.
- **Enter** — більше інформації про обраний процес.
- **M** — меню (налаштування).
- **T** — перемикання сортування (CPU / MEM).
- **K** — kill process.
- **ESC / Q** — вихід або назад.

## 🛠 Коли використовувати

- Коли хочеш **швидко побачити картину всього** — CPU, RAM, диски, мережа.
- Зручно для **живого моніторингу в терміналі**.
- Альтернатива `htop` з кращою візуалізацією.

## 📋 Як читати `atop`: структура вікна

`atop` оновлює інформацію щохвилини (за замовчуванням) і показує **зріз стану системи** на певний момент часу.

---

### 🔹 1. **Верхня частина — ресурси системи**

Приклад:

```lua
ATOP - 2025/04/17  12:30:01  -------  up 12:45,  1 user,  load avg 0.55 0.48 0.51
```

- **Дата та час**
- **Час аптайму**
- **Кількість користувачів**
- **Load average** — як у `htop`

---

### 🔹 2. **CPU:**

```lua
CPU  sys  3%  user  6%  irq  0%  idle 91%  wait  0%
```

- **sys** — ядро
- **user** — користувацькі процеси
- **idle** — вільний CPU
- **wait** — очікування I/O (якщо багато — проблеми з дисками!)

---

### 🔹 3. **MEM / SWP:**

```lua
MEM  7983M tot  1520M free  1200M cache  650M buff
SWP  2048M tot     0M used
```

- **tot** — загальна
- **free** — вільна
- **cache/buff** — кеші, які можуть звільнитися при потребі

---

### 🔹 4. **DSK:**

```lua
DSK  sda  busy 5%  read 1000 KB/s  write 500 KB/s  avio 0.50 ms
```

- **busy** — завантаження диску
- **avio** — середній час доступу до диску (в мс)
- Якщо **avio > 20ms** — можливі проблеми

---

### 🔹 5. **NET:**

```lua
NET  eth0  up 100 Mbps  rx 500 KB/s  tx 300 KB/s
```
- **rx / tx** — прийом і передача даних
- Якщо інтерфейс перевантажений — буде видно одразу

## 🧱 **iptables** — потужний і гнучкий фаєрвол

### 🔹 Що це?

`iptables` — це **низькорівневий інструмент** для керування правилами мережевого фільтрування в Linux.

### 🔧 Приклад: дозволити SSH (порт 22)

bash

CopyEdit

`sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT`

### 🔧 Заборонити все інше:

bash

CopyEdit

`sudo iptables -P INPUT DROP`

📌 Але: `iptables` **не зберігає правила після перезавантаження** без додаткових дій.

> 🧠 Потрібно вручну створювати скрипти для збереження, або використовувати `iptables-persistent`.

---

## 🟩 **ufw (Uncomplicated Firewall)** — простий інтерфейс до `iptables`

### 🔹 Що це?

`ufw` — це **зручна обгортка над `iptables`**, створена для простоти.

### 🔧 Основні команди:

- **Увімкнути фаєрвол:**
    
    bash
    
    CopyEdit
    
    `sudo ufw enable`
    
- **Дозволити SSH:**
    
    bash
    
    CopyEdit
    
    `sudo ufw allow ssh`
    
- **Або за портом:**
    
    bash
    
    CopyEdit
    
    `sudo ufw allow 22`
    
- **Перевірити статус:**
    
    bash
    
    CopyEdit
    
    `sudo ufw status verbose`
    
- **Заборонити порт:**
    
    bash
    
    CopyEdit
    
    `sudo ufw deny 80`
    
- **Вимкнути фаєрвол:**
    
    bash
    
    CopyEdit
    
    `sudo ufw disable`

## 🔥 Практична порада

- Якщо ти **DevOps-студент і хочеш просто відкрити/закрити порти** — використовуй `ufw`.
    
- Якщо треба **тонко налаштувати фільтрацію по IP/пакетам** — вчи `iptables`.
