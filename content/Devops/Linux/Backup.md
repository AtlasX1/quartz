Backup (резервне копіювання) — це процес створення копій даних, щоб мати можливість відновити їх у разі втрати, пошкодження або знищення оригіналу. Це критично важлива частина стратегії безпеки будь-якої ІТ-системи.

---

### 🔍 Навіщо потрібен backup?

1. **Захист від втрати даних:** Через помилки користувача, збої обладнання, віруси або атаки (наприклад, ransomware).
    
2. **Відновлення після катастроф:** Наприклад, пожежа в дата-центрі або повна втрата сервера.
    
3. **Архівування:** Для збереження історичних версій документів або баз даних.
    
4. **Дотримання законодавства:** Деякі компанії зобов’язані зберігати дані певний період часу.
    

---

### 🧰 Основні типи backup

|Тип|Опис|
|---|---|
|**Повне (Full backup)**|Повна копія всіх даних. Займає багато місця, але просте у відновленні.|
|**Інкрементальне (Incremental backup)**|Копіюються лише зміни з моменту останнього бекапу. Швидко створюється, але складніше відновлювати.|
|**Дельтоподібне (Differential backup)**|Копіюються зміни з моменту останнього **повного** бекапу. Баланс між обсягом і швидкістю.|

---

### 🛠️ Інструменти для резервного копіювання

- **rsync** — для синхронізації файлів.
- **tar** — для архівації даних.
- **BorgBackup**, **Restic**, **Duplicity** — сучасні CLI-інструменти для backup.
- **Velero** — для Kubernetes.
- **AWS Backup**, **Azure Backup** — хмарні рішення.

---

### 📦 Приклад простого backup-скрипта з `tar`

```bash
#!/bin/bash
# Створення резервної копії каталогу /home/user

SRC="/home/user"
DEST="/mnt/backup"
DATE=$(date +%F)

mkdir -p $DEST
tar -czf $DEST/backup-$DATE.tar.gz $SRC

echo "Резервна копія створена у $DEST/backup-$DATE.tar.gz"
```

### ✅ Рекомендації

- **Перевіряйте резервні копії.** Немає сенсу в backup, якщо він не відновлюється.
- **Зберігайте копії в кількох місцях.** Наприклад, локально + в хмарі.
- **Автоматизуйте.** Використовуйте cron або системи управління.


`rsync` — це потужна та ефективна утиліта для копіювання і синхронізації файлів та директорій як локально, так і по мережі. Вона дуже популярна серед DevOps-інженерів через свою швидкість, гнучкість і підтримку інкрементальних копій.

---
### ⚙️ Як працює `rsync`?

`rsync` порівнює джерело і місце призначення, і передає **тільки змінені частини файлів**, а не весь файл цілком. Це значно зменшує навантаження на мережу і пришвидшує процес.

---

### 🔧 Базовий синтаксис

```
rsync [опції] джерело призначення
```

---

### 📦 Приклади

#### 1. **Копіювання файлів з однієї директорії в іншу**

```bash
rsync -av /home/user/documents/ /mnt/backup/documents
```

**Пояснення:**

- `-a` — archive mode (зберігає структуру, права доступу, часи модифікації тощо).
- `-v` — verbose (виводить деталі процесу).
- `/` в кінці важливо: з ним копіює _вміст_ папки, без нього — саму папку.

#### 2. **Синхронізація між локальним та віддаленим сервером**

```bash
rsync -avz /home/user/ user@192.168.1.100:/backup/
```

- `-z` — стиснення перед передачею (добре для повільних з’єднань).
- `user@IP:/шлях/` — SSH-доступ до віддаленого сервера.

#### 3. **Видалення файлів, яких немає у джерелі**

```bash
rsync -av --delete /home/user/ /mnt/backup/user/
```

- `--delete` — видаляє файли у призначенні, яких немає у джерелі (синхронізація в один бік).

---

### 📅 Приклад автоматизації через `cron`

Щоб запускати `rsync` щодня о 3:00 ночі:
```bash
0 3 * * * /usr/bin/rsync -av /home/user/ /mnt/backup/user/ >> /var/log/rsync-backup.log 2>&1
```

Додай цей рядок до `crontab -e`.
