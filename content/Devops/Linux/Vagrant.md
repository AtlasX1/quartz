Vagrant — це інструмент для створення та управління віртуальними середовищами розробки. Його основна мета — спростити налаштування та стандартизацію середовищ, у яких працюють розробники та DevOps-фахівці.

---

### 🔹 Що таке Vagrant?
Vagrant — це CLI-інструмент, який дозволяє легко створювати віртуальні машини (VM) за допомогою простого конфігураційного файлу (`Vagrantfile`). Vagrant працює разом із провайдерами віртуалізації (наприклад, VirtualBox, VMware, Docker тощо).

---

### 🔹 Основні переваги Vagrant

- **Відтворюваність середовища:** Кожен розробник або DevOps має однакове середовище.
- **Автоматизація:** Налаштування через `Vagrantfile`.
- **Ізольованість:** Кожна VM ізольована від хост-системи.
- **Інтеграція з провайдерами:** VirtualBox, VMware, Docker та інші.

---

### 🔹 Основні компоненти

1. **Vagrantfile** — основний конфігураційний файл, який описує, як створювати та налаштовувати віртуальну машину.
2. **Box** — шаблон VM (зазвичай Linux), який Vagrant використовує для створення нових інстансів.
3. **Provider** — інструмент, що створює VM (VirtualBox, VMware, Docker).
4. **Provisioner** — система налаштування VM (наприклад, shell-скрипти, Ansible, Puppet).

---

### 🔹 Типовий `Vagrantfile`

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/bionic64"  # використовуємо Ubuntu 18.04

  config.vm.network "forwarded_port", guest: 80, host: 8080

  config.vm.provider "virtualbox" do |vb|
    vb.memory = "1024"
  end

  config.vm.provision "shell", inline: <<-SHELL
    sudo apt update
    sudo apt install -y apache2
  SHELL
end
```

### 🔹 Для чого використовується Vagrant?

- Тестування інфраструктурного коду (Ansible, Terraform)
- Розробка програмного забезпечення
- Лабораторні середовища для DevOps-практик
- Навчальні середовища

Архітектура **Vagrant** побудована навколо ідеї **керованого середовища віртуалізації**, де Vagrant є "посередником" між розробником і віртуальним середовищем. Вона має модульну структуру, де кожен компонент виконує свою роль.

## 🔹 Загальна архітектура Vagrant


```diff
+----------------+
|  Vagrant CLI   |  ← Інтерфейс користувача
+----------------+
        ↓
+----------------+
|  Vagrant Core  |  ← Обробка конфігурацій, команд, життєвого циклу VM
+----------------+
        ↓
+-------------------------+
| Provider API (VirtualBox, |
| VMware, Docker, etc.)     |
+-------------------------+
        ↓
+----------------+
| Віртуальна М.  |
| (VM / контейнер) |
+----------------+
```

## 🔹 Компоненти архітектури Vagrant

### 1. **Vagrant CLI**

Це інтерфейс командного рядка, який користувач використовує для взаємодії з Vagrant.

**Приклади команд:**
```bash
vagrant init
vagrant up
vagrant ssh
```

---

### 2. **Vagrant Core**

Це "двигун" Vagrant. Він:

- Зчитує `Vagrantfile`
- Обробляє життєвий цикл VM (start, halt, destroy)
- Працює з провайдерами та провізіонерами
- Обробляє плагіни та розширення

---

### 3. **Vagrantfile**

Це Ruby-файл конфігурації, де визначаються:
- Який **box** використати
- Який **провайдер**
- Які ресурси виділити
- Мережеві налаштування
- Команди для **provisioning**

---

### 4. **Provider (провайдер)**

Це плагін, який інтегрується з інструментами віртуалізації. Найпопулярніші:

|Provider|Пояснення|
|---|---|
|VirtualBox|Найчастіше використовується|
|VMware|Платна, більш продуктивна|
|Docker|Для легких контейнеризованих середовищ|
|Hyper-V|Для Windows-користувачів|

---

### 5. **Box**

Це готовий шаблон віртуальної машини. Наприклад, `ubuntu/bionic64`. Box'и можна:

- Завантажити з Vagrant Cloud
- Створити самостійно

---

### 6. **Provisioners**

Provisioner — це інструмент, який налаштовує VM після її створення.
Підтримувані провізіонери:
- **Shell scripts**
- **Ansible**
- **Puppet**
- **Chef**

```ruby
config.vm.provision "shell", inline: <<-SHELL
  sudo apt update
  sudo apt install -y nginx
SHELL
```

## 🔸 Як це працює крок за кроком

1. 🔧 `vagrant init` — створює `Vagrantfile`
2. 🚀 `vagrant up` — зчитує `Vagrantfile`, завантажує box, запускає VM
3. ⚙️ Provisioner налаштовує середовище
4. 📡 Ви підключаєтесь до VM через `vagrant ssh`
5. 🛑 `vagrant halt/destroy` — зупиняє або видаляє VM

Ось **повний перелік основних команд Vagrant**, розділений за категоріями для кращого розуміння. Кожна команда супроводжується коротким описом, а також прикладом використання 💡

У Vagrant є **три основні типи мережевих налаштувань**, які дозволяють підключатися до віртуальної машини або зробити її доступною ззовні. Це:

---

## 🔹 1. **Forwarded Port (Проброс портів)**

Цей тип дозволяє перенаправити порт з хост-машини на гостьову VM.

📌 **Для чого:** Наприклад, щоб доступитися до вебсервера на VM через браузер на хості.
🔧 **Vagrantfile:**
```
config.vm.network "forwarded_port", guest: 80, host: 8080
```

➡️ Тепер `http://localhost:8080` на твоїй машині відкриє `http://localhost:80` на VM.

---

## 🔹 2. **Private Network (Приватна мережа)**

Це ізольована мережа, де VM має IP, доступний тільки для хост-машини.

📌 **Для чого:** Для тестування, коли немає потреби відкривати доступ назовні, але треба мати стабільну IP-адресу.

🔧 **Vagrantfile:**
```
config.vm.network "private_network", ip: "192.168.56.10"
```
➡️ Тепер хост може звертатися до VM за IP `192.168.56.10`.

---

## 🔹 3. **Public Network (Публічна мережа)**

VM підключається до тієї ж мережі, що й хост, і отримує IP-адресу з DHCP або статично.

📌 **Для чого:** Коли треба, щоб до VM могли підключатися інші пристрої в мережі (наприклад, інші компи в офісі).

🔧 **Vagrantfile:**
```
config.vm.network "public_network"
```

➡️ Під час `vagrant up` тебе попросять вибрати мережевий інтерфейс.

---
## 🔸 Порівняння

|Тип мережі|Видимість|Статична IP|Доступ ззовні|
|---|---|---|---|
|Forwarded Port|Хост|Ні|Частково|
|Private Network|Хост|Так|Ні|
|Public Network|Вся мережа|Може бути|Так|

---
## 🔧 Кілька мереж одночасно

Можна вказати кілька типів мереж:

```ruby
config.vm.network "forwarded_port", guest: 80, host: 8080
config.vm.network "private_network", ip: "192.168.33.10"
```



**Port Forwarding** у Vagrant — це механізм, який дозволяє перенаправити трафік з певного порту на **хост-машині** до певного порту на **гостьовій (VM)** машині. Це дуже зручно, якщо ти хочеш отримати доступ до сервісу на VM через браузер чи інші інструменти на хості.

---

## 🔹 Як це працює

При запуску `vagrant up`, Vagrant створює правила пробросу портів між хостом і VM, згідно з `Vagrantfile`.

---

## 🔧 Синтаксис у `Vagrantfile`


```ruby
config.vm.network "forwarded_port", guest: 80, host: 8080
```

- `guest: 80` — порт всередині VM (де, наприклад, працює Nginx)
- `host: 8080` — порт на хості, через який ти звертаєшся

➡️ Після цього `http://localhost:8080` на твоїй хост-машині буде перенаправлятися на `http://localhost:80` у VM.

---

## 🔄 Багато портів

Можна вказати кілька портів:

```ruby
config.vm.network "forwarded_port", guest: 22, host: 2222
config.vm.network "forwarded_port", guest: 3306, host: 8306  # MySQL
```

---

## ❗ Попередження

- **Порт на хості має бути вільним.** Інакше отримаєш помилку.
- **Порти нижче 1024** на хості можуть потребувати прав адміністратора (особливо на Linux/Mac).
- **Один порт = одне правило.** Немає автоматичного злиття правил.

## 🧪 Простий приклад

1. Створи `Vagrantfile`:

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/bionic64"

  config.vm.network "forwarded_port", guest: 80, host: 8080

  config.vm.provision "shell", inline: <<-SHELL
    sudo apt update
    sudo apt install -y nginx
  SHELL
end
```
2. Запусти машину:

```bash
vagrant up
```

3. У браузері відкрий: `http://localhost:8080`

➡️ Ти побачиш стандартну сторінку **Nginx**, що працює на VM!
