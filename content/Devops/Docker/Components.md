## 🐳 `docker-ce`: Docker Community Edition (Docker Engine)

**Що це таке:**

- Це основна частина Docker — **рушій**, який запускає контейнери.
- Запускається як системний сервіс (`dockerd`), який слухає запити від клієнта Docker.

**Функції:**

- Створення, запуск, зупинка контейнерів.
- Побудова образів із Dockerfile.
- Робота з мережами, томами та зберіганням даних.

**`CE` означає** Community Edition — безкоштовна, з відкритим кодом, версія Docker.

---

## 🛠 `docker-ce-cli`: Docker CLI (Command Line Interface)

**Що це таке:**

- Інтерфейс командного рядка (`docker`), за допомогою якого ми взаємодіємо з Docker Engine.

**Функції:**

- Кожна команда, яку ти вводиш типу `docker run`, `docker build`, `docker ps` — виконується саме через CLI.
- CLI відправляє запити до сервісу `dockerd` (Docker Engine), який вже виконує відповідні дії.

---

## ⚙️ `containerd.io`: Контейнерний Runtime

**Що це таке:**

- `containerd` — це **низькорівневий сервіс**, який фактично керує життєвим циклом контейнерів.
- Він використовується **під капотом** Docker Engine (і не тільки — також Kubernetes).

**Функції:**

- Створення, запуск, зупинка, збереження контейнерів.
- Робота з образами.
- Підтримує кілька контейнерних форматів.

📌 Без `containerd` Docker Engine не зміг би запускати контейнери — це "двигун" нижчого рівня.

---

## 🏗 `docker-buildx-plugin`: Плагін для `docker buildx`

**Що це таке:**

- Розширення для побудови Docker-образів з використанням **BuildKit** — сучасної системи побудови Docker.

**Функції:**

- Підтримує побудову образів для **кількох архітектур** (наприклад, x86_64, ARM).
- Кешування, паралельна збірка, ефективніше управління залежностями.

🔧 Корисно, якщо ти створюєш образи для різних систем (наприклад, серверів і Raspberry Pi).

---

## 🧱 `docker-compose-plugin`: Плагін для `docker compose`

**Що це таке:**

- Оновлений плагін для роботи з `docker compose` як частини `docker` CLI (через `docker compose` замість старого `docker-compose`).

**Функції:**

- Можна описати кілька контейнерів у файлі `docker-compose.yml` і запустити їх однією командою.
- Зручно для запуску багатокомпонентних застосунків (наприклад, web-сервер + БД + кеш).


```bash
docker compose up 
docker compose down
```
