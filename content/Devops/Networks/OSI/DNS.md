**DNS (Domain Name System)** — це основа роботи Інтернету. Без нього ми б мусили пам’ятати **IP-адреси сайтів**, як `142.250.186.14` замість просто `google.com`. Давай розберемо **що таке DNS**, **як він працює**, **які є типи записів**, і як DevOps-фахівець може з ним працювати.


## 🧠 **Що таке DNS?**

**DNS (система доменних імен)** — це **“телефонна книга Інтернету”**, яка перетворює **доменне ім’я** (наприклад `softserveacademy.com`) у відповідну **IP-адресу** (наприклад `35.209.12.10`), яку розуміють мережеві пристрої.

---

## 🔄 **Як працює DNS? (етапи запиту)**

Коли ти вводиш в браузері `example.com`, відбувається такий процес:

1. 👀 **Перевірка локального кешу** (чи вже відома IP-адреса?)
2. 📂 **Перевірка `/etc/hosts`** (локальне зіставлення)
3. 📡 **Запит на DNS-резолвер** (від твого провайдера або Google DNS)
4. 🧭 **Пошук серед DNS-серверів:**
    - **Root DNS-сервери** → направляють до…
    - **TLD-серверів** (`.com`, `.ua`, `.org`) → направляють до…
    - **Авторитетного DNS-сервера** → повертає справжню IP-адресу
5. ✅ **Отримання IP і кешування результату**
    

📦 Приклад:

```bash
nslookup google.com
```

→ отримаєш IP-адресу `142.250.186.14`

---

## 📘 **Прикладна схема:**

`Ти → DNS-резолвер → Root DNS → TLD DNS → Авторитетний DNS → IP`

---

## 🔤 **Основні типи DNS-записів**

| Тип     | Опис                                    | Приклад                                            |
| ------- | --------------------------------------- | -------------------------------------------------- |
| `A`     | IPv4-адреса для імені                   | `example.com → 93.184.216.34`                      |
| `AAAA`  | IPv6-адреса                             | `example.com → 2606:2800:220:1:248:1893:25c8:1946` |
| `CNAME` | Канонічне ім’я (псевдонім)              | `www → example.com`                                |
| `MX`    | Поштова служба                          | `mail.example.com`                                 |
| `NS`    | DNS-сервери для зони                    | `ns1.example.com`                                  |
| `TXT`   | Текстовий запис (SPF, перевірка домену) | `"v=spf1 include:example.com"`                     |
| `PTR`   | Зворотний запис (IP → ім’я)             | `34.216.184.93.in-addr.arpa`                       |

## 🛠️ **Практичні інструменти (Linux)**

|Команда|Призначення|
|---|---|
|`nslookup <домен>`|Отримати IP-адресу|
|`dig <домен>`|Детальний DNS-запит|
|`host <домен>`|Короткий запит|
|`cat /etc/resolv.conf`|Перевірити DNS-сервери системи|
|`ping <домен>`|Перевірка резолвінгу і доступності|

## 🧠 **DNS кеш**

- **Локальний кеш**: система зберігає IP деякий час
- **TTL (Time To Live)**: вказує, скільки часу зберігати запис
```bash
systemd-resolve --statistics sudo resolvectl flush-caches
```

## 🧩 **DNS для DevOps**

- 🔧 Налаштування внутрішніх DNS (в Docker, Kubernetes, cloud)
- 🔐 Перевірка DNS-атак (наприклад, DNS spoofing)
- 🛡️ Робота з `bind9`, `dnsmasq` для локального DNS
- 🚀 Використання сервісів типу Cloudflare DNS, Google DNS (8.8.8.8)
