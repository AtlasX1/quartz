Протокол **TCP (Transmission Control Protocol)** — це **основа надійної передачі даних** в Інтернеті. Він працює на **транспортному рівні (4 рівень OSI)** та забезпечує **гарантовану доставку даних між пристроями**, незалежно від того, де вони знаходяться.


## 📦 **1. Що таке TCP?**

**TCP — це орієнтований на з’єднання протокол**, який:
- Створює **стійке з’єднання між двома хостами**
- **Гарантує доставку** всіх пакетів
- **Відновлює порядок**, якщо пакети приходять не по черзі
- Виконує **перевірку помилок**
- Керує **потоками даних**

---

## 🔄 **2. Як працює TCP?**

### 📌 **Триетапне рукостискання (3-way handshake)**

1. 🟢 Клієнт → Сервер: `SYN`
2. 🔁 Сервер → Клієнт: `SYN-ACK`
3. 🟢 Клієнт → Сервер: `ACK`

Після цього з'єднання встановлено, і починається передача даних.

---

### 📦 **Цикл передачі даних:**

1. Клієнт надсилає **TCP-сегменти** (частини даних)
2. Сервер надсилає **підтвердження (ACK)** на кожен сегмент
3. Якщо підтвердження не приходить — TCP **повторює** відправлення

---

## 🔍 **3. Структура TCP-сегменту (заголовок)**

```
| Source Port | Destination Port |
| Sequence Number |
| Acknowledgment Number |
| Flags (SYN, ACK, FIN, RST, PSH, URG) |
| Window Size |
| Checksum |
| Data |
```
### Важливі поля:

- **Sequence Number** — номер байта в потоці
- **ACK** — підтвердження прийому
- **Window Size** — контроль потоку
- **Flags** — керування станом з’єднання (`SYN`, `ACK`, `FIN`…)

---

## 🔒 **4. Завершення з’єднання (TCP Teardown)**

### 📉 Відбувається у 4 етапи:

1. Клієнт → Сервер: `FIN`
2. Сервер → Клієнт: `ACK`
3. Сервер → Клієнт: `FIN`
4. Клієнт → Сервер: `ACK`

---

## 🧪 **5. Команди для аналізу TCP-з'єднань**

### Перегляд активних з’єднань:

```bash
ss -tn        # тільки TCP netstat -tuln # застарілий, але часто зустрічається
```
### Відслідковування трафіку TCP:

```bash
sudo tcpdump -i any tcp
```

## 🧠 **7. Переваги TCP**

✅ Гарантує доставку  
✅ Перевіряє помилки  
✅ Встановлює з’єднання  
✅ Визначає правильний порядок пакетів  
✅ Контроль потоку і перевантаження

---

## ❌ **8. Недоліки TCP**

- Більше накладних витрат (заголовки, підтвердження)
- Повільніше, ніж UDP
- Не завжди ефективний для стрімінгу, ігор (там часто краще UDP)

---

## 📌 **9. TCP в DevOps**

- Налаштовуєш firewall — потрібно знати, які порти відкрити (TCP vs UDP)
- Аналіз мережі при проблемах: `ss`, `tcpdump`
- Налаштовуєш Nginx, Apache, SSH — все через TCP
- Load Balancer — працює з TCP-з'єднаннями
- Моніторинг — бачиш з'єднання, сесії, стани `ESTABLISHED`, `CLOSE_WAIT`
## 🚩 **Основні TCP-прапорці (flags)**

|Прапорець|Назва|Призначення|
|---|---|---|
|`SYN`|Synchronize|Ініціація з'єднання (початок рукостискання)|
|`ACK`|Acknowledgment|Підтвердження отримання даних або SYN|
|`FIN`|Finish|Завершення з'єднання|
|`RST`|Reset|Скидання з'єднання (наприклад, при помилці)|
|`PSH`|Push|Вказує, що дані потрібно негайно передати додатку|
|`URG`|Urgent|Вказує, що частина даних має високий пріоритет|
|`ECE`|ECN Echo|Сигнал про перевантаження (з ECN-сумісними пристроями)|
|`CWR`|Congestion Window Reduced|Відповідь на `ECE`, зменшення вікна потоку|

---

## 🤝 **Рукостискання TCP (3-way handshake)**

|Крок|Прапорці|
|---|---|
|1. Клієнт → Сервер|`SYN`|
|2. Сервер → Клієнт|`SYN`, `ACK`|
|3. Клієнт → Сервер|`ACK`|

Після цього з’єднання встановлено ✅

---

## 📉 **Завершення TCP-з’єднання**

|Крок|Прапорці|
|---|---|
|1. Один бік → інший|`FIN`, `ACK`|
|2. Інший бік → перший|`FIN`, `ACK`|
|3. Перший бік → інший|`ACK`|

---

## 🧪 **Перегляд прапорців у реальному трафіку**


```bash
sudo tcpdump -i any tcp
```
Або для аналізу:

```bash
sudo tcpdump -i any 'tcp[tcpflags] & tcp-syn != 0'
```

> Можна побачити SYN, ACK, FIN та інші прапорці в реальному часі.

---

## 📘 **Сценарії використання прапорців**

| Прапорець | Сценарій                                       |
| --------- | ---------------------------------------------- |
| `SYN`     | Старт нової TCP-сесії                          |
| `RST`     | Несподіване завершення (сервер не слухає порт) |
| `FIN`     | Коректне завершення сесії                      |
| `PSH`     | Дані повинні бути одразу доставлені            |
| `URG`     | Наприклад, термінове повідомлення або сигнал   |
