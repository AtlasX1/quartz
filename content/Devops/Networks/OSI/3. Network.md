**Network Layer (мережевий рівень)** — це **третій рівень моделі OSI**, і він один із **найважливіших для DevOps-інженера**. Саме він відповідає за **доставку пакетів між пристроями**, навіть якщо ті знаходяться **в різних мережах**, на великій відстані


## 🌐 **1. Що таке Network Layer?**

**Мережевий рівень**:

- Визначає **маршрут доставки даних** від відправника до одержувача через одну або більше мереж.
- Працює з **IP-адресами**.
- Відповідає за **маршрутизацію**, **фрагментацію**, **вибір найкращого шляху**.
- Забезпечує логічну адресацію (на відміну від MAC на рівні 2).

---

## 🧠 **2. Основні функції Network Layer**

|Функція|Пояснення|
|---|---|
|🧭 **Маршрутизація (Routing)**|Визначення найкращого шляху до цілі|
|🆔 **IP-адресація**|Присвоєння та використання унікальних IP-адрес|
|🧩 **Фрагментація пакетів**|Розбиття великих пакетів на менші (для MTU)|
|🔁 **Пересилання (Forwarding)**|Передача пакету до наступного вузла|
|📡 **Інкапсуляція**|Пакети інкапсулюються у кадри рівня 2|

---

## 🔢 **3. IP-адресація**

- IP-адреса: **унікальний ідентифікатор пристрою в мережі**
- Складається з **мережевої частини** і **хостової**

### IPv4 (32 біти):

```
192.168.1.10/24
```
### IPv6 (128 біт):

```
fe80::1ff:fe23:4567:890a
```

📌 Мережа `/24` означає: 255.255.255.0 → 256 IP, з яких 254 доступні

---

## 📦 **4. Основні протоколи мережевого рівня**

|Протокол|Призначення|
|---|---|
|**IP (Internet Protocol)**|Основний протокол — логічна адресація|
|**ICMP (Internet Control Message Protocol)**|Повідомлення про помилки (використовується в `ping`, `traceroute`)|
|**ARP (Address Resolution Protocol)**|Перетворення IP-адреси в MAC (рівень 2 ↔ 3)|
|**RARP**|Зворотна операція до ARP|
|**OSPF, RIP, BGP**|Протоколи маршрутизації (динамічна маршрутизація)|

---

## 📍 **5. Структура IP-пакету (IPv4)**

```
| Версія | Заголовок | Довжина | ІР відправника | ІР отримувача | Дані |
```
Може включати:

- TTL (час життя)
- Fragment Offset
- Checksum
- Протокол (TCP, UDP, ICMP…)

---

## 🔀 **6. Маршрутизація**

Мережевий рівень **не лише адресує**, але й вирішує **як дістатися** до одержувача.

### Типи маршрутизації:

|Тип|Опис|
|---|---|
|📘 **Статична**|Адміністратор вручну задає маршрут|
|🤖 **Динамічна**|Протоколи самі визначають найкращі шляхи (OSPF, RIP, BGP)|

📌 Переглянути маршрути:
```
ip route
```
---

## 🔁 **7. Фрагментація і MTU**

Кожне середовище має **максимальний розмір пакета (MTU)**, зазвичай:

- Ethernet → 1500 байт
    

Якщо пакет більший — **розбивається на фрагменти**, що вимагає збору на кінцевому хості.

---

## 🔧 **8. Приклади команд DevOps-діагностики**

```
ip a                   # Показати IP-адресу інтерфейсів
ip route               # Таблиця маршрутів
ping 8.8.8.8           # Перевірити доступність (ICMP)
traceroute google.com  # Маршрут до хоста
arp -a                 # Показати ARP-кеш
```

---

## 🧠 **9. Як все працює разом**

📘 Сценарій: Ти відкриваєш сайт `example.com`:

1. DNS → отримуєш IP-адресу (наприклад, `93.184.216.34`)
2. **Мережевий рівень** створює IP-пакет з цією адресою
3. Пакет відправляється маршрутом через мережі
4. На кожному маршрутизаторі **IP-адреса отримувача не змінюється**, лише **MAC-адреси змінюються** на кожному хопі
5. Пакет доходить до сервера → віддається на обробку

---

## 📌 Для DevOps-інженера важливо:

- Розуміти, **як дані рухаються через мережі**
- Уміти **налагоджувати маршрутизацію**
- Використовувати інструменти типу `ping`, `traceroute`, `ip route`
- Знати, як працює NAT, CIDR, VPN, Firewall на рівні IP
