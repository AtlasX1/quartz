## 🟨 **7 РІВЕНЬ — APPLICATION (ЗАСТОСУВАННЯ)**

Цей рівень містить **протоколи для прикладних програм**, які надають **сервіси кінцевому користувачу** (веб, пошта, обмін файлами).

### 📋 Основні протоколи Application Layer:

|Протокол|Призначення|
|---|---|
|**HTTP / HTTPS**|Обмін веб-сторінками, API|
|**FTP / SFTP / FTPS**|Передача файлів|
|**SSH**|Віддалений захищений доступ|
|**SMTP / POP3 / IMAP**|Електронна пошта|
|**DNS**|Перетворення імен на IP|
|**Telnet**|Старий текстовий доступ до пристроїв|
|**SNMP**|Моніторинг і керування мережевим обладнанням|
|**NTP**|Синхронізація часу|
|**LDAP**|Запити до каталогів користувачів (наприклад, AD)|
|**RDP**|Віддалений графічний доступ до Windows|
|**NetBIOS, SMB**|Спільний доступ до файлів/друку (Windows мережі)|
|**TFTP**|Легка передача файлів, без підтвердження (на основі UDP)|

---

## 🟩 **6 РІВЕНЬ — PRESENTATION (ПОДАННЯ)**

Цей рівень відповідає за **форматування, кодування, стиснення, шифрування** даних. Він забезпечує, щоб передані дані були **зрозумілі одержувачу**.

### 📋 Основні протоколи / технології Presentation Layer:

|Технологія / Протокол|Призначення|
|---|---|
|**TLS / SSL**|Шифрування HTTPS, SMTP, IMAP, FTP тощо|
|**ASCII / UTF-8 / Unicode**|Кодування тексту|
|**MIME**|Кодування мультимедійного контенту в email|
|**JPEG / PNG / MP3 / MP4 / GZIP / Brotli**|Стиснення / формат даних|
|**Base64**|Перетворення двійкових даних у текст|
|**JSON / XML / YAML / CSV**|Формати структурованих даних|
|**ASN.1**|Бінарне кодування даних (у мережевих протоколах, зокрема SNMP, X.509)|

---

## 🟦 **5 РІВЕНЬ — SESSION (СЕАНС)**

Цей рівень керує **встановленням, підтримкою та завершенням сеансів зв’язку** між двома сторонами. Він потрібен для підтримки **довготривалого, синхронного обміну даними**.

### 📋 Основні протоколи Session Layer:

|Протокол|Призначення|
|---|---|
|**NetBIOS**|Сеанси для обміну в мережах Windows|
|**RPC (Remote Procedure Call)**|Віддалене виконання функцій|
|**SIP (Session Initiation Protocol)**|Сигналізація для VoIP-з’єднань|
|**RTSP**|Керування потоковим відео|
|**PPTP / L2TP / IKE**|Керування VPN-сеансами|
|**X.225 / ISO 8327**|Формальні ISO-протоколи для сесій|
|**NFS (частково)**|Сеансове з'єднання для обміну файлами|

📌 Багато сучасних протоколів (наприклад, **SSH, TLS, HTTP/2**) вже включають **сеансову логіку**, тому окремі протоколи Session Layer використовуються рідше — але логіка збереження сесій дуже актуальна.

---

## 📌 Порівняння всіх трьох рівнів:

|Рівень|Що робить|Приклади|
|---|---|---|
|**Application (7)**|Комунікація з користувачем / програмою|HTTP, FTP, DNS, SMTP|
|**Presentation (6)**|Шифрує, стискає, форматує|TLS, JPEG, JSON, UTF-8|
|**Session (5)**|Керує сеансом / з’єднанням|RPC, SIP, RTSP, NetBIOS|

---

## 🧠 Чому це важливо для DevOps?

- 🔐 **HTTPS, TLS, сертифікати** — Presentation Layer
    
- 🌐 **REST API, DNS, SSH, Docker Registry** — Application Layer
    
- 🎮 **VPN, тунелі, багатопоточна передача** — Session Layer
    
- 🛠️ **Моніторинг, CI/CD, логування** — взаємодіють з усіма трьома рівнями
