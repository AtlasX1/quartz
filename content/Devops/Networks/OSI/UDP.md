**UDP (User Datagram Protocol)** — це **протокол транспортного рівня (4-й рівень OSI)**, як і TCP, але з дуже **іншою філософією**. Якщо TCP — це "надійний поштар з квитанціями", то **UDP — це "сміливий кур'єр без зайвих питань"** 😊

UDP — **легкий, швидкий**, але **не гарантує доставку, черговість, чи контроль помилок**. Його головна перевага — **мінімальна затримка та накладні витрати**.

## 🧠 **1. Що таке UDP?**

UDP — це **"ненадійний, безз'єднальний протокол"**, який:

- Не встановлює з'єднання перед передачею
- Не перевіряє, чи дійшов пакет до адресата
- Не гарантує порядок доставки
- Не повторює передачу при втраті
- Передає дані **як є**, дуже швидко

---

## 🏎️ **2. Коли використовують UDP?**

|Використання|Причина|
|---|---|
|🎥 Відео та аудіо стрімінг (YouTube, Zoom, Twitch)|Затримка критичніша, ніж втрата пакета|
|🎮 Онлайн-ігри|Важлива швидкість реакції|
|📞 VoIP|Голосові дзвінки не потребують повторення пакетів|
|🔍 DNS|Короткі швидкі запити|
|💬 NTP|Синхронізація часу|

---

## 📦 **3. Структура UDP-дейтаграми (заголовок)**

UDP дуже простий — усього 4 поля в заголовку (8 байт):

`| Source Port | Destination Port | | Length | Checksum |`

А далі — **дані**.

✅ Немає:

- підтверджень (ACK)
- контроль порядку
- керування потоком

---

## 🔢 **4. Порти UDP**

Такі самі як у TCP, але використовуються іншими програмами.

|Сервіс|Порт|Протокол|
|---|---|---|
|DNS|53|UDP|
|DHCP|67/68|UDP|
|NTP|123|UDP|
|TFTP|69|UDP|
|WireGuard|51820|UDP|

## 🧪 **5. Практика в Linux**

### 📡 Відправити DNS-запит:

```bash
dig @8.8.8.8 google.com
```

### 🔎 Перегляд UDP-з'єднань:

```bash
ss -un       # лише UDP
```
### 🧾 Аналіз UDP-трафіку:

```bash
sudo tcpdump udp
```

---

## 🔍 **6. UDP vs TCP: порівняння**

|Критерій|TCP|UDP|
|---|---|---|
|Надійність|✅ Так|❌ Ні|
|Порядок доставки|✅ Так|❌ Ні|
|Підтвердження (ACK)|✅|❌|
|Контроль потоку|✅|❌|
|Швидкість|Повільніше|🚀 Швидше|
|Обсяг заголовка|20 байт|8 байт|
|Використовується для|HTTP, SSH|DNS, VoIP, ігри|
