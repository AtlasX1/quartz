**Data Link Layer (Канальний рівень)** — це **другий рівень моделі OSI**, і він надзвичайно важливий, бо відповідає за **надійну передачу даних** **між двома пристроями в межах однієї мережі (LAN)**.

Цей рівень — **міст між фізичним кабелем і логікою передачі даних**.

## 🧱 **1. Що таке Data Link Layer?**

🔹 Це рівень, який:

- **Отримує біти з фізичного рівня** й **формує з них кадри** (frames)
- Додає **MAC-адреси** для ідентифікації відправника та одержувача
- **Виявляє та виправляє помилки**
- **Керує доступом до середовища передавання** (наприклад, у Wi-Fi)

---

## 🧠 **2. Основні функції канального рівня**

|Функція|Опис|
|---|---|
|🧱 Формування кадрів|Об’єднує біти у логічні блоки — **кадри (frames)**|
|🧭 Адресація|Вставляє **MAC-адресу** відправника й одержувача|
|🛡️ Виявлення помилок|CRC-контроль цілісності кадру|
|🚦 Керування доступом|Визначає, хто і коли може передавати дані|
|🔁 Повторна передача|У деяких протоколах — повторює кадри, якщо є помилки|

---

## 🔍 **3. Підрівні Data Link Layer**

Data Link Layer має 2 підрівні:

### 1️⃣ **LLC (Logical Link Control)**

- Керує логікою зв’язку, мультиплексуванням (TCP/UDP)
- Встановлює та підтримує логічне з’єднання

### 2️⃣ **MAC (Media Access Control)**

- Фізичні MAC-адреси
- Контролює доступ до фізичного середовища (CSMA/CD для Ethernet, CSMA/CA для Wi-Fi)

---

## 🏷️ **4. MAC-адресація**

- Кожен мережевий інтерфейс має **унікальну MAC-адресу**
- MAC-адреса: 48-бітове число (6 байт), записується як:

```
00:1A:2B:3C:4D:5E
```

- 📥 **Destination MAC**
- 📤 **Source MAC**

MAC-адреси не змінюються при передачі в межах LAN.

---

## 🔧 **5. Формат Ethernet-кадру (спрощено)**

```
| Preamble | Dest MAC | Src MAC | Type | Payload | CRC |
```

- **Preamble** — синхронізація
- **Dest MAC / Src MAC** — адреси
- **Type** — тип протоколу (наприклад, IPv4)
- **Payload** — дані
- **CRC** — контрольна сума

---

## 📡 **6. Протоколи канального рівня**

|Протокол|Середовище|Особливості|
|---|---|---|
|**Ethernet**|Кабель|Найпоширеніший у LAN|
|**802.11 (Wi-Fi)**|Бездротове|Має механізм CSMA/CA|
|**PPP**|Точка-точка (DSL)|Легкий, простий|
|**Frame Relay / ATM**|WAN|Використовувались раніше|

---

## 🧪 **7. Як побачити канальний рівень у Linux**

### 🔍 Перевірити MAC-адресу:

```
ip link
```
### 🔧 Змінити MAC (спуфінг):

```
sudo ip link set dev eth0 down
sudo ip link set dev eth0 address 00:11:22:33:44:55
sudo ip link set dev eth0 up
```
### 📡 Перевірити ARP-кеш (зв’язок IP ↔ MAC):

```
ip neigh
```

---
## 🧠 **8. Взаємодія з вищими рівнями**

Коли ти надсилаєш HTTP-запит:

1. На рівні 3 — пакет отримує IP-адресу
2. На рівні 2 — пакет інкапсулюється в кадр з MAC-адресами
3. Кадр передається через кабель
4. Switch читає MAC-адресу і передає на потрібний порт

---
## 📘 Приклад — як працює Ethernet в LAN

1. Твій ноутбук хоче зв’язатися з принтером:
2. У ARP-кеші немає MAC принтера → надсилається ARP-запит
3. Принтер відповідає зі своєю MAC
4. Тепер твої кадри йдуть до нього напряму через switch

---
## 🧠 Для DevOps важливо:

- Розуміти, як **switch маршрутизує кадри за MAC**
- Вміти працювати з **ARP, MAC-адресами**
- Знати, як **мережа поводиться в LAN без IP (наприклад, на DHCP етапі)**
