**Application Layer (рівень застосування)** — це **7-й, найвищий рівень моделі OSI**, і він **найближчий до користувача або застосунків**. Тут відбувається **взаємодія з програмами**, які використовують мережу: браузери, поштові клієнти, FTP, месенджери, CI/CD-інструменти — усе це працює на цьому рівні.
## 🧠 **Що таке Application Layer?**

**Application Layer** — це рівень, який забезпечує **інтерфейс між користувачем (або програмою) і мережею**.

📌 На цьому рівні:

- Дані стають “зрозумілими” для користувача/програми
- Використовуються **конкретні протоколи** для взаємодії з сервісами
- Розпочинається **мережева активність** (напр., HTTP-запит)

---
## 🧩 **Основні функції Application Layer**

|Функція|Пояснення|
|---|---|
|📞 Ініціація комунікації|Користувач або застосунок починає мережеву взаємодію|
|📜 Визначення сервісу|Який сервіс потрібен? (веб, пошта, файл тощо)|
|🔐 Аутентифікація|Перевірка користувача (наприклад, при логіні на сайт)|
|📡 Передача даних|Обмін структурованими даними (HTML, JSON, email...)|
|🛠️ Взаємодія з нижчими рівнями|Передача запитів далі до Presentation/Session/Transport|

---
## 🌐 **Приклади протоколів Application Layer**

|Протокол|Призначення|Порт|
|---|---|---|
|**HTTP / HTTPS**|Веб (браузери, API)|80 / 443|
|**DNS**|Перетворення доменів на IP|53|
|**FTP / SFTP**|Передача файлів|21 / 22|
|**SMTP / IMAP / POP3**|Надсилання і отримання пошти|25 / 143 / 110|
|**SSH**|Віддалений доступ до терміналу|22|
|**Telnet**|Старий текстовий протокол|23|
|**LDAP**|Доступ до каталогів (Active Directory)|389|
|**NFS / SMB**|Спільний доступ до файлів у мережі|2049 / 445|
|**DHCP**|Автоматична видача IP-адрес|67 / 68|

## 📘 Як виглядає робота Application Layer (на прикладі HTTP)
1. Ти відкриваєш браузер і вводиш `http://example.com`
2. **Application Layer** створює HTTP-запит:

```http
GET /index.html HTTP/1.1 Host: example.com
```

3. Дані спускаються вниз (Presentation → Transport → Network…)
4. Сервер відповідає на рівні застосування:

```http
HTTP/1.1 200 OK Content-Type: text/html <html>...</html>
```

---

## 🧠 **Application Layer vs Presentation vs Session**

|Рівень|Що робить|
|---|---|
|**Application**|Запуск запиту (напр. HTTP, FTP, SSH)|
|**Presentation**|Шифрує, стиснює, форматує (напр. TLS, JSON, ASCII)|
|**Session**|Керує сеансом (установлення/завершення з’єднання)|

## 🧪 **Практика (DevOps щоденна робота)**

|Завдання|Приклад|
|---|---|
|🔧 Тест API|`curl http://localhost:8000/api/status`|
|📡 Перевірка DNS|`dig google.com`|
|📂 Передача файлів|`scp file.txt user@host:/path/`|
|🚀 Розгортання вебсервера|Nginx працює на порту 80 (HTTP)|
|🛡️ Налаштування firewall|Відкрити порти для HTTP, SSH|
|🧾 Перевірка логу|`tail -f /var/log/nginx/access.log` — бачиш запити рівня застосування|

## 🧠 Чому важливо знати Application Layer?

- 👨‍💻 Це рівень, з яким **взаємодіє DevOps кожного дня**
- 🛠️ Тут **працюють всі сервіси і API**, які ти налаштовуєш
- 🔍 Знаючи цей рівень, ти зможеш **швидше знаходити помилки**
- 🔒 Це рівень, де важливі **автентифікація, безпека, логування**
