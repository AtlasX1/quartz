🌐 **Протоколи (Protocols)** — це набір правил, за якими пристрої в мережі обмінюються даними. Вони гарантують, що інформація буде **доставлена правильно, вчасно і зрозуміло** для обох сторін.

Протоколи працюють на **різних рівнях моделі OSI або TCP/IP**. 

---

## 📦 **1. IP (Internet Protocol)**

- Відповідає за **адресацію** і **маршрутизацію** пакетів.
- Визначає, куди надіслати пакет (IP-адреса одержувача).
- **IP не гарантує доставку**, просто намагається передати дані.

📌 **IP-версії:**

- IPv4: `192.168.1.1`
- IPv6: `fe80::1ff:fe23:4567:890a`

---

## 🔄 **2. TCP (Transmission Control Protocol)**

- **Надійний протокол**, який гарантує доставку.
- Дані передаються як потік байтів, з підтвердженнями (ACK).
- Використовується для **HTTP, HTTPS, FTP, SSH** тощо.

📦 Механізми:
- Рукостискання (3-way handshake)
- Контроль помилок
- Перезапис втраченої інформації

---

## 💨 **3. UDP (User Datagram Protocol)**

- **Швидкий, але ненадійний**.
- Немає підтвердження отримання, контроль менший.
- Використовується для **стрімінгу, VoIP, DNS-запитів**.

📌 Приклад:
- Відеодзвінок, де важливіше швидко отримати звук, навіть якщо втрачено кілька мілісекунд.

---

## 🌍 **4. HTTP/HTTPS (HyperText Transfer Protocol)**

- Протоколи для **веб-запитів**.
- **HTTP** — нешифрований, **HTTPS** — захищений за допомогою SSL/TLS.

📦 Приклад:

```
GET /index.html HTTP/1.1 Host: example.com
```

> HTTPS використовує **порт 443**, HTTP — **порт 80**.

---

## 🗂️ **5. FTP (File Transfer Protocol)**
- Для **передачі файлів** між клієнтом і сервером.
- Має версію **SFTP (через SSH)** або **FTPS (через SSL)** для захисту.

📌 Команди:
```
ftp ftp.example.com
```

---

## 📛 **6. DNS (Domain Name System)**

- Перетворює **доменні імена на IP-адреси**.
- Наприклад: `google.com` → `142.250.186.14`

📦 Приклад:

```
nslookup google.com
```

---

## 🧷 **7. DHCP (Dynamic Host Configuration Protocol)**

- Автоматично видає IP-адресу та інші параметри мережі (шлюз, DNS).
- Дуже зручно в локальних мережах.

---

## 🛡️ **8. SSH (Secure Shell)**

- Протокол **захищеного доступу до віддаленого сервера**.
- Основний інструмент DevOps! 💻

📌 Приклад:
```
ssh user@192.168.1.100
```

---

## 🛰️ **9. ICMP (Internet Control Message Protocol)**

- Використовується для **діагностики та повідомлень про помилки**.

📌 Приклад:
```
ping 8.8.8.8
```

> `ping`, `traceroute` використовують ICMP.

---

## 📊 Порівняння протоколів

|Протокол|Призначення|Порт|Надійність|
|---|---|---|---|
|TCP|Надійна доставка|80, 443, 22|Висока|
|UDP|Швидка передача без гарантії|53, 69|Низька|
|HTTP/HTTPS|Веб-доступ|80 / 443|HTTP - ні, HTTPS - так|
|FTP|Передача файлів|21 / 22 (SFTP)|Середня|
|SSH|Доступ до серверів|22|Висока|
|DNS|Перетворення доменів|53|Висока|
|DHCP|Автоматична конфігурація|67/68|Висока|

---

## 🧪 Практика

Ти можеш спробувати ці команди прямо в терміналі:
```
ping google.com            # перевірка ICMP
nslookup github.com        # DNS-запит
curl https://example.com   # HTTP/HTTPS
ftp ftp.debian.org         # FTP
ssh user@host              # SSH
```
