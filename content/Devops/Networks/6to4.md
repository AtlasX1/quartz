🌍 Протокол **6to4** — це один зі способів **переходу з IPv4 на IPv6**. Це автоматичний **тунелюючий механізм**, який дозволяє пристроям з IPv6-стеком спілкуватися через наявну IPv4-мережу без потреби в зміні інфраструктури.

---

## 📦 Що таке 6to4?

**6to4** — це **техніка інкапсуляції IPv6-пакетів у IPv4-пакети**. Вона дозволяє відправляти IPv6-трафік через IPv4-мережу, використовуючи спеціальний **IPv6-префікс, згенерований із IPv4-адреси**.

---

## 🧠 Основна ідея:

1. У тебе є **IPv4-адреса**, наприклад `192.0.2.4`
2. З неї автоматично формується IPv6-адреса з префіксом `2002::/16`
3. Отже, твоя 6to4-адреса буде:
    `2002:c000:0204::/48`
    - `c000` = `192` у hex
    - `0204` = `2.4` у hex
4. Така адреса використовується для відправки IPv6-пакетів через IPv4-інтернет

---

## 🛠 Як працює передача даних:

- Пакет IPv6 інкапсулюється всередині **IPv4-пакета з протоколом 41** (IPv6 over IPv4)
- На іншому кінці тунелю — інший 6to4-хост або **6to4-реле (relay router)**, який розпаковує IPv6 і пересилає далі

---

## 📌 Структура 6to4-адреси:

|Компонент|Значення|
|---|---|
|`2002::/16`|Префікс, зарезервований для 6to4|
|`c000:0204`|IPv4-адреса у hex (тут 192.0.2.4)|
|`/48`|Префікс для мережі|
|Наступні 16 біт|Для субмереж|
|Решта|Інтерфейсний ідентифікатор|

### 🔍 Приклад:

IPv4: `203.0.113.17` → hex: `cb00:7111`

IPv6-адреса:

`2002:cb00:7111::1`

---

## 🌐 Чим корисний 6to4?

✅ **Автоматичний** — не треба вручну налаштовувати тунелі

✅ **Глобальна адресація IPv6** — можна отримати унікальні IPv6-адреси навіть без провайдера, що підтримує IPv6

---

## ⚠️ Проблеми та недоліки:

🚫 **Нестабільність**: залежить від зовнішніх relay-роутерів

🚫 **Відсутність NAT-сумісності**: не працює добре за NAT (а NAT — всюди в IPv4)

🚫 **Відсутність безпеки**: пакет просто інкапсулюється у IPv4 без шифрування

🚫 **Застарілий механізм**: сьогодні практично **не використовується**, замінений на сучасніші механізми, як-от **Teredo**, **ISATAP** або **IPv6 native**

---

## 🔧 Як увімкнути 6to4 (на прикладі Linux):


```bash
ip tunnel add tun6to4 mode sit remote any local 192.0.2.4 ttl 255
ip link set tun6to4 up
ip -6 addr add 2002:c000:0204::1/16 dev tun6to4
ip -6 route add 2000::/3 via ::192.88.99.1 dev tun6to4
```

> `192.88.99.1` — стандартна 6to4 relay-адреса (може вже не працювати, бо 6to4 вийшов з обігу)

🌐 **Miredo** — це **реалізація протоколу Teredo для Unix-систем** (зокрема, для Linux), яка дозволяє пристроям отримувати **IPv6-підключення через IPv4 NAT**. Це особливо корисно, коли:

- Ваш провайдер **не підтримує IPv6**
    
- Ви знаходитесь **за NAT**, і пряме IPv6-з'єднання неможливе
    
- Потрібен **тунель IPv6 через IPv4**, без ручної конфігурації
    

---

## 🔎 Що таке **Teredo**?

**Teredo** — це протокол, розроблений Microsoft, який дозволяє тунелювати IPv6 через IPv4, **навіть якщо пристрій знаходиться за NAT**. Використовується протокол **UDP (порт 3544)**.

Miredo — це **відкрита реалізація Teredo** для *nix-платформ.

---

## 📦 Що таке **Miredo**?

|Пункт|Значення|
|---|---|
|Назва|**Miredo**|
|Призначення|Надати IPv6 через Teredo-тунель|
|Платформи|Linux, BSD, MacOS|
|Протокол|UDP/IPv4 тунель, що переносить IPv6|
|Порт|UDP 3544|

Miredo створює **віртуальний інтерфейс**, зазвичай `teredo`, через який передається IPv6-трафік.


```yaml

    inet6 2001:0:53aa:64c:0:5efe:abcd:1234/128 scope global 
```

---

## 🧠 Як працює Miredo / Teredo:

1. **Створюється тунель** між вашим хостом і **Teredo-сервером** (наприклад, `teredo.remlab.net`)
2. **IPv6-пакети інкапсулюються в IPv4 UDP** і передаються через NAT
3. На сервері ці пакети розпаковуються і передаються далі по IPv6

---

## 🌐 Приклад сценарію:

1. Ви маєте лише IPv4 з NAT (наприклад Wi-Fi вдома)
2. Встановлюєте `miredo`
3. Ваш хост отримує **публічну IPv6-адресу**, хоч навіть NAT це не дозволяє напряму
4. Ви можете `ping6`, `curl`, `ssh` до IPv6-ресурсів

## ⚠️ Обмеження:

|Обмеження|Опис|

- Розуміти, що Miredo відкриває зовнішній IPv6-інтерфейс
