🔄 **Тунелювання (tunneling)** — це техніка, яка дозволяє **пересилати один протокол "всередині" іншого**, тобто "загортати" один тип мережевого трафіку у пакети іншого типу, щоби **пройти через несумісну або обмежену мережу**.

---

## 🧠 Проста аналогія:

Уяви, що ти хочеш надіслати **лист українською**, але поштова служба приймає лише **англійські конверти**. Ти загортаєш свій лист у такий конверт — і він успішно доходить. Одержувач відкриває конверт і читає український лист.

🧩 **Лист** — це реальний трафік (наприклад, IPv6)  
📩 **Конверт** — транспортний протокол (наприклад, IPv4)  
📬 **Маршрут** — мережа, яка "не знає" про IPv6, але підтримує IPv4

---

## 📦 Як працює тунелювання?

1. **Інкапсуляція**: дані одного протоколу (напр. IPv6) вбудовуються у пакети іншого протоколу (напр. IPv4).
    
2. **Передача**: пакети передаються по існуючій інфраструктурі.
    
3. **Декапсуляція**: на іншому кінці пакети "розпаковуються", і відновлюються оригінальні дані.
    

---

## 🎯 Навіщо використовують тунелювання?

|Сценарій|Пояснення|
|---|---|
|🛣 Перехід IPv4 → IPv6|Наприклад, 6to4, Teredo, ISATAP, які дозволяють IPv6-трафіку проходити через IPv4|
|🔐 VPN-з'єднання|Протоколи типу OpenVPN, IPsec — для захищеної передачі|
|🔄 Передача несумісного трафіку|Наприклад, multicast через unicast|
|🧪 Тестування нових протоколів|Без зміни існуючої інфраструктури|

---

## 📘 Типи тунелювання:

|Тип|Приклад|Протоколи|
|---|---|---|
|🎫 Прозоре|IPv6 в IPv4|6to4, ISATAP, Teredo|
|🔒 Захищене|VPN|OpenVPN, IPsec, WireGuard|

## 🔧 Приклад: тунель IPv6 через IPv4

### Сценарій:

Ти хочеш `ping6 ipv6.google.com`, але маєш лише IPv4-інтернет.  
**Тунель вирішує проблему**:

1. Система бере IPv6-пакет
2. Вбудовує його у IPv4 (протокол 41 або UDP)
3. Надсилає через IPv4-мережу
4. На іншому кінці тунель розпаковує пакет і передає у мережу IPv6

---

## 🛠 Команди прикладу:

### GRE тунель:

```bash
ip tunnel add gre1 mode gre remote 198.51.100.1 local 203.0.113.1 ttl 255 ip link set gre1 up ip addr add 192.168.10.1/30 dev gre1
```
