# Big O аналіз складності: Строгий каркас

> **Аудиторія:** L4 інженери | **Фокус:** Асимптотична нотація, щільність, практичні константи, приховані складності

## 🎯 Концептуальний огляд

**Big O нотація** обманливо проста: $f(n) = O(g(n))$ означає $\exists c, n_0$ такі що $f(n) \leq c \cdot g(n)$ для всіх $n \geq n_0$.

Але це приховує критичні тонкості:

1. **Верхня vs нижня vs щільна межи:** O, Ω, Θ мають різні значення
2. **Константи мають значення:** O(n) з c=0.1 перемагає O(n) з c=1000 поки n не величезне
3. **Приховані терміни:** O(n log n) може бути $n \log_2(n) + 100n + 50$
4. **Амортизована vs гірший випадок:** Кардинально різні практичні наслідки

На L4 рівні ви повинні:
- Точно аналізувати складність свого коду
- Виявляти приховані O(n²) баги (вкладені цикли, приховані цикли)
- Розуміти коли теорія складності рухається (константи, ефекти кешу)
- Комунікувати точно про компроміси

## 📍 1. Асимптотична нотація: Строгі визначення

### 1.1 Big-O: Верхня межа

**Визначення:** $f(n) = O(g(n))$ iff $\exists c > 0, n_0$ такі що:
$$0 \leq f(n) \leq c \cdot g(n) \text{ для всіх } n \geq n_0$$

**Інтерпретація:** f зростає не швидше за g (до константи).

**Приклади:**
- $3n^2 + 2n + 1 = O(n^2)$ (виберемо c=4, n₀=1)
- $n \log n = O(n^2)$ (істинно але слабко)
- $2^n = O(3^n)$ (технічно істинно але марно)

**Поширена помилка:** Плутанина O з Θ. O(n²) — це **верхня межа**, не щільна.

### 1.2 Big-Omega: Нижня межа

**Визначення:** $f(n) = \Omega(g(n))$ iff $\exists c > 0, n_0$ такі що:
$$f(n) \geq c \cdot g(n) \text{ для всіх } n \geq n_0$$

**Інтерпретація:** f зростає принаймні так само швидко як g.

**Приклади:**
- $3n^2 + 2n + 1 = \Omega(n^2)$ (виберемо c=1, n₀=1)
- $n \log n = \Omega(n)$ (виберемо c=1, n₀=2)
- $2^n = \Omega(n^{100})$ (істинно для всіх поліномів)

### 1.3 Theta: Щільна межа

**Визначення:** $f(n) = \Theta(g(n))$ iff $f(n) = O(g(n))$ ТА $f(n) = \Omega(g(n))$

Еквівалентно: $\exists c_1, c_2, n_0$ такі що:
$$c_1 \cdot g(n) \leq f(n) \leq c_2 \cdot g(n) \text{ для всіх } n \geq n_0$$

**Інтерпретація:** f та g зростають з однаковою швидкістю (до констант).

**Приклади:**
- $3n^2 + 2n + 1 = \Theta(n^2)$
- $n \log n = \Theta(n \log n)$
- $2^n \neq \Theta(3^n)$ (експоненціали з різними основами відрізняються)

### 1.4 Маленькі-O та маленькі-Omega

**Визначення:** $f(n) = o(g(n))$ (маленьке-o) iff:
$$\lim_{n \to \infty} \frac{f(n)}{g(n)} = 0$$

**Значення:** f строго домінується g.

**Приклади:**
- $n = o(n^2)$ (квадратичне строго краще)
- $n \log n = o(n^{1.1})$ (будь-який поліном > O(n log n))
- $n \neq o(n)$

**Визначення:** $f(n) = \omega(g(n))$ (маленьке-omega) iff g = o(f).

## 📍 2. Техніки аналізу

### 2.1 Ієрархія порядку зростання

Для великого n, наступне зростає від найшвидшого до найповільнішого:

$$1 < \log n < \sqrt{n} < n < n \log n < n^2 < n^3 < \ldots < 2^n < 3^n < n!$$

**Ключові переходи:**
- $n^{0.5}$ перетинає $\log n$ біля n = 16
- $n^{1.5}$ перетинає $n \log n$ біля n = 8
- $2^n$ експлодує: при n=60, 2ⁿ ≈ 10¹⁸

**Практичний вплив:**
- n ≤ 10⁶: O(n log n) комфортно
- n ≤ 1000: O(n²) допустимо
- n ≤ 20: O(2ⁿ) здійсненно

### 2.2 Аналіз простого коду

**Приклад 1: Вкладені цикли**

```
for i = 0 to n-1:
  for j = 0 to n-1:
    constant_work()
```

Аналіз:
- Зовнішній цикл: n ітерацій
- Внутрішній цикл: n ітерацій на кожну зовнішню
- Всього: n × n = **O(n²)**

**Приклад 2: Вкладені цикли з break**

```
for i = 0 to n-1:
  for j = i to n-1:
    constant_work()
```

Аналіз:
- i=0: внутрішній запускається n разів
- i=1: внутрішній запускається n-1 разів
- ...
- i=n-1: внутрішній запускається 1 раз

Всього: n + (n-1) + ... + 1 = $\frac{n(n+1)}{2} = \Theta(n^2)$

**Приклад 3: Бінарний пошук**

```
while left < right:
  mid = (left + right) / 2
  if array[mid] < target:
    left = mid + 1
  else:
    right = mid
```

Аналіз:
- Кожна ітерація: простір пошуку половинюється
- Ітерацій: $\log_2(n)$
- **Складність: O(log n)**

### 2.3 Рекурентні відношення

**Master Theorem (вже розглядалось у розділі Алгоритми)**

Для T(n) = aT(n/b) + f(n):

1. Якщо $a > b^d$ де $f(n) = O(n^d)$: **T(n) = Θ(n^{log_b a})**
2. Якщо $a = b^d$: **T(n) = Θ(n^d log n)**
3. Якщо $a < b^d$: **T(n) = Θ(n^d)**

**Приклад: Підрахування інверсій**

T(n) = 2T(n/2) + O(n)

- a=2, b=2, d=1
- a = b^d (випадок 2)
- Результат: **T(n) = Θ(n log n)**

### 2.4 Амортизований аналіз

**Проблема:** Деякі операції O(1), інші O(n). Яка "істинна" складність?

**Амортизований аналіз:** Розподіліть вартість дорогих операцій над багатьма дешевими.

**Приклад: Динамічний масив з подвоєнням**

```
push операції: 1, 2, 3, 4, 5, 6, 7, 8 (resize при 8)
витрати:       1, 1, 1, 1, 1, 1, 1, 8
```

Загальна вартість для 8 pushes: 1+1+1+1+1+1+1+8 = 16 = O(8)

Амортизована вартість на push: 16/8 = **O(1)**

**Метод бухгалтерії:** Стягуйте кожну push на 2 одиниці:
- 1 одиниця: виконайте push
- 1 одиниця: заощадьте для майбутнього перевиділення

Коли перевиділення відбувається, накопичені заощадження оплачують це.

**Формальна амортизована межа:** Якщо n операцій коштує T(n) загалом, амортизована вартість = T(n)/n на операцію.

## 📍 3. Приховані складності на практиці

### 3.1 Операції зі строками в JavaScript

**Операції JavaScript зі строками приховують складність:**

- `str.substring(i, j)`: O(j - i) — потрібно скопіювати підстроку
- `str[i]`: O(1) — доступ до символу
- `str1 + str2`: O(|str1| + |str2|) — потрібно виділити і скопіювати
- `str.split(',')`: O(n) — потрібно сканувати і створити масив

**Прихована квадратична складність:**

```
let result = '';
for (let i = 0; i < 100000; i++) {
  result += 'x';  // O(i) на ітерацію
}
// Всього: 1 + 2 + 3 + ... + 100000 = O(n²)
```

Кожна `+=` виділяє нову строку і копіює усі попередні символи.

**Виправлення:** Використовуйте масив та join: O(n)

```
let result = [];
for (let i = 0; i < 100000; i++) {
  result.push('x');  // O(1) амортизовано
}
let str = result.join('');  // O(n)
// Всього: O(n)
```

### 3.2 Операції з масивом

**Операції JavaScript з масивом:**

- `push()`: O(1) амортизовано
- `pop()`: O(1)
- `shift()`: O(n) — зміщує всі елементи
- `unshift()`: O(n)
- `splice(i, 1)`: O(n - i) — зміщує все після i
- `arr[i]`: O(1)
- `arr.indexOf(x)`: O(n) — лінійне сканування
- `for (let x of arr)`: O(n)

**Прихована квадратична складність:**

```
let arr = [];
for (let i = 0; i < 1000; i++) {
  arr.unshift(i);  // O(i) на ітерацію
}
// Всього: O(n²)
```

**Виправлення:** Будуйте в зворотному порядку, push (O(1) амортизовано), потім reverse

### 3.3 Операції Set та Map

**JavaScript Set/Map:**

- `set.add(x)`: O(1) в середньому
- `set.has(x)`: O(1) в середньому
- `set.delete(x)`: O(1) в середньому
- `set.size`: O(1)
- `for (let x of set)`: O(n)

**Ключова ідея:** "В середньому" припускає хороше розповсюдження хешу. Антагоністичне введення може спричинити O(n) операції (колізії).

### 3.4 Вкладені ітерації з прихованими операціями

**Прихований паттерн складності:**

```
for (let user of users) {           // O(n)
  for (let order of user.orders) {  // O(m) на користувача
    console.log(order);
  }
}
// Всього: O(n × m)
```

Якщо `orders.length` варіюється, складність залежить від загальної кількості замовлень у всіх користувачів.

**Інший паттерн (небезпечний):**

```
for (let item of array) {
  let index = array.indexOf(item);  // O(n) на ітерацію!
  // ...
}
// Всього: O(n²)
```

## 📍 4. Просторова складність

### 4.1 Стек викликів

**Рекурсивні виклики витрачають простір стека:**

```
function factorial(n) {
  if (n <= 1) return 1;
  return n * factorial(n-1);
}
```

Простір: O(n) — n кадрів стека

**Оптимізація хвостової рекурсії (у мовах що це підтримують):**

```
function factorial(n, acc = 1) {
  if (n <= 1) return acc;
  return factorial(n-1, acc*n);  // Може оптимізувати в цикл
}
```

Простір: O(1) якщо компілятор оптимізує

### 4.2 Допоміжні структури даних

**Виділення додаткових масивів:**

```
let arr = new Array(n);  // O(n) простір
let matrix = Array(n).fill(null).map(() => Array(n));  // O(n²) простір
```

**Прихований простір у рекурсії:**

Дерево бінарного пошуку має n вузлів, кожен з 2 вказівниками:
- Простір: O(n)

Збалансоване сортування потребує O(log n) тимчасових масивів для об'єднання:
- Загальний простір: O(n + log n) = O(n)

### 4.3 Ієрархія простору

$$O(1) < O(\log n) < O(\sqrt{n}) < O(n) < O(n \log n) < O(n^2) < O(2^n)$$

**Практичні границі:**
- O(n): ~10⁷ елементів (100 MB)
- O(n log n): ~10⁶ елементів (відсортовано)
- O(n²): ~10³ елементів (матриці)
- O(2ⁿ): ~20 елементів максимум

## 📍 5. Практичні границі та константи

### 5.1 Правило 10 мільйонів

Для практичної продуктивності на сучасному обладнанні:

**O(n) на 10⁷ елементів:** ~100 мс
**O(n log n) на 10⁶ елементів:** ~100 мс
**O(n²) на 10³ елементів:** ~100 мс
**O(2ⁿ) для n=20:** ~100 мс

Це грубі рекомендації; фактична продуктивність залежить від:
- Констант факторів
- Поведінки кешу
- Ширини пропускання пам'яті
- Констант алгоритму

### 5.2 Коли теорія рухається

**Сценарій 1: Маленький n**

Для n < 100, O(n²) часто перемагає O(n log n) завдяки кращій локальності кешу і меншим константам.

**Сценарій 2: Ефекти кешу**

Ітерація масиву (відмінний кеш) може перемогти теоретично краще алгоритми на пов'язаних структурах (поганий кеш).

**Сценарій 3: Константи факторів**

Quicksort: T(n) ≈ 1.38 n log n
Heapsort: T(n) ≈ 4.0 n log n

Quicksort може бути в 3× швидше незважаючи на однакову асимптотичну складність.

### 5.3 Практичні константи у виборі алгоритму

**При виборі алгоритмів розгляньте:**

1. **Розповсюдження розміру задачі:** Більшість даних <100 елементів? Використовуйте простий O(n²)
2. **Поведінка кешу:** Переважно алгоритми дружні до кешу
3. **Константи факторів:** Вимірюйте, не вгадуйте
4. **Зрілість реалізації:** Реалізації stdlib часто вагомо оптимізовані
5. **Обмеження пам'яті:** Іноді пам'ять важить більше ніж час

## 📍 6. Помилки та невірні уявлення про складність

### 6.1 Поширені помилки

**Помилка 1: Плутанина O з Θ**

```
// НЕВІРНО: "Цей цикл це O(n)"
for (let i = 0; i < n; i += 2) {
  work();
}
```

**Коректно:** O(n) — це верхня межа (істинно але слабко). Повинні сказати Θ(n) для щільної межі.

**Помилка 2: Ігнорування логарифмічних основ**

```
O(log₂ n) vs O(log₁₀ n): відрізняються на 3.32×
```

В асимптотичній нотації різні основи не мають значення. Але на практиці мають!

**Помилка 3: Приховані цикли у викликах функцій**

```
let arr = [...bigArray];  // O(n) копія!
arr.sort();               // O(n log n)
// Всього: O(n log n), не O(n)
```

**Помилка 4: Припущення що "менша O" завжди краще**

```
Algo A: O(n log n) з c = 1000
Algo B: O(n²) з c = 1

Для n < 1000, Algo B швидше!
```

### 6.2 Трюки аналізу

**Трюк 1: Виявлення прихованих циклів**

Шукайте виклики функцій що ітерують. Приклади:
- `arr.includes(x)`: O(n)
- `str.indexOf(x)`: O(n)
- `arr.map(f)`: O(n) (якщо f це O(1))

**Трюк 2: Сума геометричного ряду**

Якщо подвоєння відбувається k разів з вартістю 2^i:
$$\sum_{i=0}^{k} 2^i = 2^{k+1} - 1 \approx 2 \cdot 2^k = O(2^k)$$

**Трюк 3: Гармонійний ряд**

1 + 1/2 + 1/3 + ... + 1/n = Θ(log n)

## 📍 7. Точна комунікація про складність

### 7.1 Як правильно висловити складність

**Погано:** "Цей алгоритм це O(n)"

**Добре:** "Цей алгоритм має часову складність O(n) та просторову складність O(1)"

**Ще краще:** "Для розміру введення n, алгоритм виконує приблизно 3n + 2 порівнянь, з амортизованим O(1) на операцію"

### 7.2 Найкращий, середній, гірший випадки

**Quicksort:**
- Найкращий випадок: O(n log n) — збалансований pivot
- Середній випадок: O(n log n) — випадковий pivot
- Гірший випадок: O(n²) — відсортоване введення, pivot в кінці

Завжди уточнюйте який випадок ви аналізуєте.

### 7.3 Складність vs константи vs кеш

**Повний аналіз повинен включати:**

```
Часова складність: O(n log n)
Константа фактора: ≈ 1.2 n log n порівнянь
Поведінка кешу: Хороша (послідовний доступ до пам'яті)
Простір: O(n) допоміжного (для merge)
```

Це дає повну картину для дизайнерів систем.

## 💡 Питання рівня Senior

1. **Чому амортизована O(1) push має значення незважаючи на те що окремі pushes можуть бути O(n)?**
   - Відповідь: Над довгою послідовністю операцій, O(1) на операцію досяжно

2. **Наведіть алгоритм O(n) простору що здається потребувати O(n²) інтуїтивно.**
   - Відповідь: Merge sort потребує лише O(n) тимчасового простору, не O(n²)

3. **Коли б ви вибрали алгоритм O(n²) над O(n log n)?**
   - Відповідь: Менші константи, кращий кеш, простіша реалізація, менший n

4. **Як ви виявили б приховані O(n) операції при перегляді коду?**
   - Відповідь: Шукайте виклики функцій (indexOf, includes, map) всередині циклів

5. **Докажіть що бінарний пошук це Θ(log n), не просто O(log n).**
   - Відповідь: Кожна ітерація половинює простір, потребує Ω(log n) ітерацій у гіршому випадку

## 🔑 Ключові висновки

1. **O, Ω, Θ — це різне:** Не плутайте верхні/нижні/щільні межи
2. **Константи мають значення:** Для практичних розмірів, O(n²) може перемогти O(n log n)
3. **Приховані операції:** Конкатенація рядків, зміщення масиву, колізії хешу
4. **Амортизований аналіз:** Розподіліть дорогі операції над багатьма дешевими
