# Алгоритми та розв'язання задач: Глибокий аналіз

> **Аудиторія:** L4 інженери | **Фокус:** Математичні парадигми, нижні межі складності, дизайн алгоритмів

## 🎯 Концептуальний огляд

Алгоритм — це **послідовність дискретних кроків, що розв'язує обчислювальну задачу**. На відміну від структур даних (які організують дані), алгоритми організують **процес розв'язання**.

**Фундаментальне питання:** Для заданої задачі, який **мінімальний обчислювальний ресурс** (час, пам'ять) необхідний?

На L4 рівні ви мусите:
- Розуміти **нижні межі** (можемо ли ми краще за O(n log n)?), а не просто знати O-нотацію
- Розпізнавати **структуру задачі** (динамічне програмування vs greedy vs розділ-і-володарюй)
- Аналізувати **рекурентні відношення** через Master Theorem
- Обирати алгоритми на основі **реальних констант**, не тільки асимптотики

## 📍 1. Сортування: Інформаційно-теоретичні межі

### 1.1 Нижня межа для порівняльного сортування

**Теорема:** Будь-який алгоритм сортування на основі порівнень вимагає **Ω(n log n)** порівнянь у гіршому випадку.

**Доведення через теорію інформації:**

Сортування n елементів — це розмістити один з n! можливих порядків.

Кожне порівняння дає **2 можливі результати** (a < b або a ≥ b), отже дерево рішень має:
- Глибину ≥ log₂(n!) 
- За формулою Стірлінга: log₂(n!) ≈ n log₂(n) - n/ln(2)

Отже: **Нижня межа = Ω(n log n)**

Це **абсолютна межа** — жоден алгоритм на основі порівнень не може бути швидшим.

### 1.2 Алгоритми, що досягають нижної межі

**MergeSort:** O(n log n) у всіх випадках
- Стійкий: зберігає відносний порядок рівних елементів
- Вимагає O(n) додаткової пам'яті
- Кількість порівнянь: ≈ n log₂(n) - n + 1

**HeapSort:** O(n log n) у всіх випадках
- На місці (in-place): O(1) додаткова пам'ять
- Не стійкий
- Гірші cache性能 за MergeSort

**QuickSort:** O(n log n) у середньому
- Середній випадок: ≈ 2n ln(n) порівнянь
- Гірший випадок: O(n²) при поганому виборі pivot
- На практиці часто найшвидший через cache locality

### 1.3 Лінійне сортування: вихід за границі порівнянь

**Ідея:** Якщо обійтися без порівнянь, можна сортувати швидше!

**CountingSort:** O(n + k), де k = діапазон значень
- Припущення: цілі числа в [0, k)
- Алгоритм: підрахувати кількість кожного значення, відновити масив
- Недоцільне при k >> n

**RadixSort:** O(n × d), де d = кількість цифр
- Сортує по цифрах від найменш до найбільш значущої
- Базовий алгоритм (підсортування): CountingSort
- Ефективне при малій кількості цифр (d = O(log n))

**Ключова ідея:** За допомогою **non-comparison** операцій обходимо Ω(n log n) нижню межу.

## 📍 2. Динамічне програмування: Структура та закономірності

### 2.1 Визначення через принцип оптимальності

**Динамічне програмування (DP)** застосовується до задач з властивістю **оптимальної підструктури**:

> Оптимальне розв'язання задачі містить оптимальні розв'язання підзадач.

**Формалізація:**

Нехай OPT(n) = оптимальне значення для задачі розміру n.

OPT(n) визначається через: OPT(n) = f(OPT(n₁), OPT(n₂), ...) + cost(n)

де n₁, n₂, ... < n — розміри підзадач.

**Приклад: Fibonacci**

F(n) = F(n-1) + F(n-2), з базовими випадками F(0)=0, F(1)=1

Оптимальна підструктура: F(n) явно залежить від F(n-1) і F(n-2)

### 2.2 Наївна рекурсія vs Мемоїзація

**Наївна рекурсія для Fibonacci:**

```
T(n) = T(n-1) + T(n-2) + O(1)
```

Рекурентне дерево:
- На рівні i: 2ⁱ вузлів
- Висота: n
- Всього вузлів: Σ(2ⁱ) = 2ⁿ⁺¹ - 1 = **O(2ⁿ)**

Експоненціальна складність! F(50) потребує ~2⁵⁰ ≈ 10¹⁵ операцій.

**Мемоїзація (табуляція):**

Зберігаємо результати F(0), F(1), ..., F(n) в массиве.

Кожне значення обчислюється **один раз**:
- Часова складність: O(n)
- Просторова складність: O(n)

Від експоненціальної до лінійної! 

**Ключова ідея:** DP торгує пам'яттю за час, зберігаючи проміжні результати.

### 2.3 Типи DP: Top-Down vs Bottom-Up

**Top-Down (Мемоїзація):**
- Рекурсивна функція з кешем
- Обчислює лише потрібні підзадачі
- Природний порядок: від великої до малої задачі

**Bottom-Up (Табуляція):**
- Ітеративна заповнення таблиці
- Обчислює всі підзадачі, навіть непотрібні
- Краща cache locality, менше overhead від рекурсії

**Яку обирати?**
- Top-Down: Коли підзадачі розріджені (не всі потрібні)
- Bottom-Up: Коли більшість підзадач потрібна, велика частина проблеми

### 2.4 Класичні задачі та їх структура

**0/1 Knapsack:**

OPT(i, w) = максимальна вартість, використовуючи перші i предметів і ємність w

Рекурентне відношення:
```
OPT(i, w) = max(
  OPT(i-1, w),                    // не беремо предмет i
  OPT(i-1, w - weight[i]) + value[i]  // беремо предмет i
)
```

Базовий випадок: OPT(0, w) = 0

Складність: O(n × W), де W = ємність

**Longest Common Subsequence (LCS):**

OPT(i, j) = довжина LCS перших i символів першого рядка та перших j другого

Рекурентне відношення:
```
OPT(i, j) = 
  - OPT(i-1, j-1) + 1,  якщо s1[i] == s2[j]
  - max(OPT(i-1, j), OPT(i, j-1)),  інакше
```

Складність: O(m × n)

**Matrix Chain Multiplication:**

Для послідовності матриць A₁, A₂, ..., Aₙ, знайти оптимальний порядок множення.

OPT(i, j) = мінімум скалярних операцій для множення матриць i до j

```
OPT(i, j) = min(
  OPT(i, k) + OPT(k+1, j) + cost(i, k, j)
) для всіх i ≤ k < j
```

Складність: O(n³)

### 2.5 Майстер-функція для DP

**Загальна форма складності DP:**

Якщо підзадача розмірів {n₁, n₂, ..., nₖ}, то:

$$T(n) = c + \sum_{i=1}^{k} T(n_i)$$

где c = час на комбінацію результатів.

**Приклад:**
- Fibonacci: T(n) = 2T(n-1) + O(1) з мемоїзацією стає T(n) = O(n)
- Knapsack: T(n, W) = O(nW) (двовимірна таблиця)

## 📍 3. Розділ і володарюй: Рекурентні відношення

### 3.1 Структура розділ-і-володарюй

Алгоритм розв'язує задачу розміру n шляхом:

1. **Розділ:** Розбити на a підзадач розміру n/b
2. **Володарюй:** Рекурсивно розв'язати кожну підзадачу
3. **Комбінуй:** Об'єднати розв'язання за час D(n)

**Рекурентне відношення:**

$$T(n) = aT(n/b) + D(n)$$

### 3.2 Master Theorem

Для T(n) = aT(n/b) + f(n), де a ≥ 1, b > 1:

**Теорема (Master):** Нехай $f(n) = O(n^d)$, де $d \geq 0$.

1. Якщо $a > b^d$: **T(n) = Θ(n^{log_b a})** — рекурсія домінує
2. Якщо $a = b^d$: **T(n) = Θ(n^d log n)** — рекурсія та робота вирівняні  
3. Якщо $a < b^d$: **T(n) = Θ(n^d)** — робота на верхньому рівні домінує

**Приклади:**

**MergeSort:** T(n) = 2T(n/2) + O(n)
- a=2, b=2, d=1
- Перевірка: a = 2 = 2¹ = b^d (випадок 2)
- Результат: **T(n) = Θ(n log n)** ✓

**BinarySearch:** T(n) = 1·T(n/2) + O(1)
- a=1, b=2, d=0
- Перевірка: a = 1 < 2⁰ = 1... фактично a = b^d (випадок 2)
- Результат: **T(n) = Θ(log n)** ✓

**StrassenMatrixMult:** T(n) = 7T(n/2) + O(n²)
- a=7, b=2, d=2
- Перевірка: a = 7 > 2² = 4 (випадок 1)
- Результат: **T(n) = Θ(n^{log₂ 7}) ≈ Θ(n^{2.81})** (краще за O(n³))

### 3.3 Дерево рекурсії: Інтуїтивне розуміння

Для T(n) = aT(n/b) + f(n):

- **Рівень 0:** 1 задача розміру n, час f(n)
- **Рівень 1:** a задач розміру n/b, час a·f(n/b)
- **Рівень 2:** a² задач розміру n/b², час a²·f(n/b²)
- ...
- **Рівень log_b(n):** a^{log_b(n)} = n^{log_b(a)} задач розміру 1

Загальний час:
$$T(n) = \sum_{i=0}^{\log_b(n)} a^i f(n/b^i)$$

Залежно від того, яка сума більша, домінує або рекурсія, або робота на верхньому рівні.

## 📍 4. Greedy алгоритми: Оптимальність через локальний вибір

### 4.1 Структура Greedy алгоритму

Greedy алгоритм дає локально оптимальний вибір на кожному кроці, сподіваючись на глобальну оптимальність.

**Не завжди працює!** Потребує доведення оптимальності.

### 4.2 Huffman кодування: Greedy оптимальна

**Задача:** Кодувати текст мінімальною довжиною, використовуючи двійкові коди.

**Greedy алгоритм (Huffman):**
1. Створити лист для кожного символу з його частотою
2. Поки одне дерево:
   - Вибрати два листи з найменшою частотою
   - Об'єднати в нове внутрішнє вузло з частотою = сумі
   - Додати обидва в пріоритетну чергу

**Довідка оптимальності:** Huffman дерево мінімізує середню довжину кодування через **принцип обміну** (exchange argument):

Якщо існує оптимальне дерево, що відрізняється від Huffman, його можна перетворити на Huffman дерево без збільшення вартості.

**Складність:** O(n log n) з heap

### 4.3 MST (Minimum Spanning Tree)

**Задача:** Для графа з ребрами, знайти дерево (V-1 ребер), що з'єднує всі вершини з мінімальною сумою ваг.

**Kruskal (Greedy by edges):**
1. Відсортувати ребра по вазі
2. Для кожного ребра (u, v) в порядку зростання:
   - Якщо u та v у різних компонентах, додати ребро
3. Результат: MST

**Dovide через Cut Property:**

Для будь-якого розрізу графа мінімальне ребро, що перетинає розріз, входить в деякий MST.

Kruskal виконує цей вибір оптимально.

**Складність:** O(E log E) для сортування + O(E α(V)) для Union-Find = O(E log E)

### 4.4 Обмеження Greedy

**Приклад: Longest Path в DAG**

Greedy вибір найдовшого ребра на кожному кроці **не гарантує оптимальність**.

Правильне розв'язання: динамічне програмування через топологічне сортування.

**Висновок:** Greedy потребує доведення оптимальності для конкретної задачі.

## 📍 5. Backtracking: Систематичний пошук

### 5.1 Визначення та структура

Backtracking — це техніка пошуку, яка:
1. Будує розв'язання поступово
2. Відмовляється від розв'язку, що не може привести до оптимальності
3. Повертається (backtrack) та пробує інший шлях

**Простір рішень:** Дерево можливих виборів

Кількість вузлів у дереві: потенційно експоненціальна, але **pruning** зменшує вели цину дерева.

### 5.2 N-Queens: Класичний приклад

**Задача:** Розмістити n королев на дошці n×n так, щоб жодна не атакувала іншу.

**Backtracking підхід:**
1. Розташовуємо королеву у рядку 0
2. Для кожного стовпця у рядку 1:
   - Перевіряємо, безпечна ли позиція
   - Якщо так, розмістити та перейти до рядку 2
   - Якщо ні, спробувати наступний стовпець
3. Якщо знайти розв'язок, запитати, потрібно ли інше
4. Якщо ні можна розмістити у рядку k, backtrack до рядка k-1

**Складність:**
- Простір рішень: n! можливих розташувань
- З ефективним pruning: ~O(n!) у гіршому випадку, але набагато менше на практиці

### 5.3 Constraint Satisfaction Problems (CSP)

Backtracking + pruning стратегії:

**Forward Checking:** Коли призначимо значення змінній, видалити неусумісні значення з інших змінних.

**Arc Consistency (AC-3):** Видалити значення, які неможливо задовольнити іншими змінними.

Це різко зменшує простір рішень.

## 📍 6. Графові алгоритми: Структура та парадигми

### 6.1 DFS та Topological Sort

**DFS (Глибинний пошук):** 

Основна операція: відвідати вершину, потім рекурсивно відвідати всі сусідні невідвідані вершини.

**Властивості:**
- Досліджує глибоко один шлях, потім повертається
- Дерево DFS кодує структуру графа: tree edge, back edge, forward edge, cross edge

**Topological Sort (для DAG):**

Послідовність вершин така, що для кожного ребра (u, v), u з'являється перед v.

Алгоритм: Виконати DFS, додавати вершину до стека після обробки всіх сусідів. Потім обернути стек.

**Складність:** O(V + E)

### 6.2 BFS та найкоротший шлях у невважених графах

**BFS (Пошук у ширину):**

Рівень за рівнем — спочатку все на відстані 1, потім 2, тощо.

Відстань від s до v = найкоротша довжина шляху = кількість ребер.

**Властивості:**
- Знаходить найкоротший шлях у невважених графах
- Порядок відвідання = order по відстані від s

**Складність:** O(V + E)

### 6.3 Dijkstra: Найкоротший шлях з невід'ємними вагами

**Алгоритм:** Greedy + релаксація ребер

На кожному кроці:
1. Вибрати невідвідану вершину з найменшою відстанню від s
2. Для кожного сусіда v цієї вершини:
   - Якщо distance[v] > distance[u] + weight(u, v), розслабити (update)

**Інваріант:** У кожен момент знаємо найкоротший шлях до всіх обраних вершин.

**Складність:**
- З бінарною heap: O((V + E) log V)
- З Fibonacci heap: O(E + V log V) — теоретично оптимально

**Чому не працює з негативними вагами?** 

Dijkstra вибирає вершину та ніколи не переглядає її. Але з негативними ребрами, відстань може змінитися через інші шляхи.

### 6.4 Bellman-Ford: Негативні ваги та виявлення циклів

**Алгоритм:**

Повторити V-1 разів: для кожного ребра (u, v), розслабити його.

На V-му кроці: якщо відстань змінилась, існує негативний цикл.

**Складність:** O(V × E)

**Порівняння:**
- Dijkstra: O((V+E) log V), але не працює з негативними вагами
- Bellman-Ford: O(V×E), працює з негативними, виявляє цикли

Bellman-Ford медленніше, але універсальніший.

### 6.5 All-Pairs Shortest Paths

**Floyd-Warshall:**

Динамічне програмування: OPT(i, j, k) = найкоротший шлях від i до j, використовуючи вершини {1, ..., k} як проміжні.

Рекурентне:
```
OPT(i, j, k) = min(
  OPT(i, j, k-1),            // не використовуємо k
  OPT(i, k, k-1) + OPT(k, j, k-1)  // використовуємо k
)
```

**Складність:** O(V³)

**Коли використовувати:**
- V малий (< 500): Floyd-Warshall простіший
- V великий, граф розріджений: Run Dijkstra з кожної вершини = O(V(E + V) log V)

## 📍 7. Рядкові алгоритми: Пошук та зіставлення

### 7.1 Knuth-Morris-Pratt (KMP)

**Задача:** Знайти всі входження рядка pattern у текст text.

**Наївний алгоритм:** O(n × m) у гіршому випадку

**KMP ідея:** Використовувати інформацію про невдачі пошуку, щоб уникнути повторювання.

**LPS массив (Longest Proper Prefix that is Suffix):**

Для кожної позиції k у pattern, знайти довжину найдовшого префікса, що є суфіксом pattern[0..k].

Приклад: pattern = "ABABAB"
```
LPS = [0, 0, 1, 2, 3, 4]
```

**Алгоритм:**
1. Побудувати LPS: O(m)
2. Пошук: O(n), використовуючи LPS для переходу

**Складність:** O(n + m)

### 7.2 Rabin-Karp: Хешування для пошуку

**Ідея:** Хешувати pattern та кожне вікно текста розміру m. Порівнювати хеші.

**Rolling hash:** Для вікна [i, i+1, ..., i+m-1]:

hash = (text[i] × b^(m-1) + text[i+1] × b^(m-2) + ... + text[i+m-1]) mod p

Наступне вікно: hash_new = ((hash - text[i]×b^(m-1)) × b + text[i+m]) mod p

**Складність:**
- Середній випадок: O(n + m)
- Гірший випадок: O(n × m) (при частих хеш-колізіях)

**Переваги над KMP:** Простіший код, легко узагальнити на багато patterns.

### 7.3 Z-Algorithm

Побудувати Z массив: Z[i] = довжина найдовшого підрядка text[i..], що також є префіксом text.

**Складність:** O(n)

**Застосування:** Пошук всіх входжень pattern у text в O(n + m).

## 🎯 Таблиця парадигм алгоритмів

| Парадигма | Властивість | Коли використовувати | Приклади |
|---|---|---|---|
| Divide & Conquer | Розділити, розв'язати підзадачі, комбінувати | Незалежні підзадачі | MergeSort, BinarySearch, Strassen |
| Dynamic Programming | Оптимальна підструктура + перекриття | Залежні підзадачі, перекриття | Knapsack, LCS, Fibonacci |
| Greedy | Локально оптимальний вибір | Задача має greedy-вибір властивість | Huffman, Kruskal, Dijkstra |
| Backtracking | Систематичний пошук з pruning | Перечисли все з обмеженнями | N-Queens, CSP, Sudoku |
| BFS | Level-by-level пошук | Найкоротший шлях (невважений) | Топологія, зв'язність |
| DFS | Глибокий пошук | Топологія, цикли, сильна зв'язність | Topological Sort, SCC |

## 💡 Senior-рівневі питання на співбесідах

1. **Master Theorem не охоплює T(n) = 2T(n/2) + n log n. Як аналізувати?**
   - Відповідь: Використати дерево рекурсії або розширену Master Theorem

2. **Чому Quicksort краще за MergeSort на практиці, хоча обидва O(n log n)?**
   - Відповідь: Cache locality, in-place операції, менший стал-за жди

3. **Доведіть, що Huffman кодування оптимально.**
   - Відповідь: Exchange argument з опис подіб двох листів з мінімальною частотою

4. **Як знайти найдовший простий шлях у графі за поліноміальний час?**
   - Відповідь: Неможливо (NP-hard), якщо немає спеціальної структури (DAG → O(V+E))

5. **Dijkstra не працює з негативними вагами. Чому саме?**
   - Відповідь: Вибирає вершину як "остаточну" без переглядів. Негативне ребро може змінити відстань пізніше.

## 🔑 Ключові висновки

1. **Нижні межі мають значення:** Ω(n log n) для порівняльного сортування — це абсолютна межа
2. **DP vs Greedy:** DP для залежних підзадач, Greedy для незалежних (з доведенням)
3. **Master Theorem** швидко аналізує рекурентні відношення розділ-і-володарюй
4. **Граф-алгоритми специалізовані:** BFS для невважених, Dijkstra для невід'ємних, Bellman-Ford для загального
5. **Рядкові алгоритми розповсюджені:** KMP для точного пошуку, Rabin-Karp для множення patterns
